Business Rules — backend

설계 결정 요약 (backend-functional-design-plan.md 답변)

# 결정
Q1 상태와 예상 시간은 주문 줄 단위. 수량이 2 이상이어도 줄 하나가 전부 나가야 완료
Q2 주문 번호는 한국 시간(KST) 자정에 초기화
Q3 수량 1~20, 한 주문 최대 20줄, 예상 시간 1~120분(정수)
Q4 안 나간 메뉴가 있어도 이용 완료 허용. 화면 확인 팝업에 남은 개수 표시
Q5 비밀번호를 바꿔도 이미 발급된 태블릿 토큰은 만료까지 유효
Q6 주문 삭제로 주문이 0건이 되어도 세션 유지
Q7 데모 seed: 매장 demo, 관리자 admin/admin1234, 테이블 1~6(1234), 메뉴 12개

BR-AUTH. 인증

ID 규칙
BR-AUTH-1 관리자 로그인 입력은 매장 식별자, 사용자명, 비밀번호입니다. 태블릿 로그인 입력은 매장 식별자, 테이블 번호, 비밀번호입니다.
BR-AUTH-2 매장이 없음, 사용자/테이블이 없음, 비밀번호 불일치는 같은 오류(INVALID_CREDENTIALS)로 응답합니다. 어느 값이 틀렸는지 알려주지 않습니다.
BR-AUTH-3 비밀번호는 bcrypt 해시로만 저장합니다. 평문은 어디에도 저장하지 않습니다(태블릿 localStorage는 예외로 수용 — requirements.md FR-C1).
BR-AUTH-4 관리자 토큰과 태블릿 토큰은 모두 유효 시간이 16시간입니다. 토큰에는 종류(admin/table), store_id, admin_id 또는 table_id가 들어갑니다.
BR-AUTH-5 관리자 토큰으로 태블릿 API를, 태블릿 토큰으로 관리자 API를 호출할 수 없습니다(종류 불일치 → 401).
BR-AUTH-6 토큰은 서버가 저장하지 않습니다(무상태). 로그아웃으로 서버 쪽 무효화는 없습니다.
BR-AUTH-7 테이블 비밀번호를 바꿔도 이미 발급된 태블릿 토큰은 만료될 때까지 유효합니다. 다음 자동 재로그인에서 새 비밀번호로 실패해 설정 화면으로 이동합니다. (Q5: A)
BR-AUTH-8 SSE 연결은 쿼리 파라미터 토큰을 같은 규칙으로 검증합니다. 이미 연결된 스트림은 토큰이 만료돼도 연결 중에는 유지하고, 재연결 시 다시 검증합니다.

BR-LOCK. 로그인 시도 제한

ID 규칙
BR-LOCK-1 잠금 키는 (종류, 매장 식별자, 식별자)입니다. 관리자는 사용자명, 태블릿은 테이블 번호가 식별자입니다. 기기 단위가 아니라 계정(테이블) 단위입니다.
BR-LOCK-2 로그인 실패가 연속 5회가 되면 그 시점부터 15분 동안 잠급니다(locked_until = 5번째 실패 시각 + 15분).
BR-LOCK-3 잠금 중에는 비밀번호가 맞아도 거부합니다(ACCOUNT_LOCKED, 해제 시각 포함). 잠금 중의 시도는 실패 횟수와 잠금 시각을 늘리지 않습니다.
BR-LOCK-4 잠금 시간이 지난 뒤 첫 시도에서 실패 횟수를 0으로 초기화하고 정상 검증을 진행합니다.
BR-LOCK-5 로그인에 성공하면 실패 횟수를 0으로 초기화합니다.
BR-LOCK-6 존재하지 않는 매장/사용자로 시도해도 같은 방식으로 횟수를 기록해서, 존재 여부가 응답 차이로 드러나지 않게 합니다.

BR-ORDER. 주문 생성

ID 규칙
BR-ORDER-1 주문은 태블릿 토큰으로만 만들 수 있고, 주문의 매장·테이블은 토큰에서 정합니다. 요청 본문의 매장/테이블 값은 받지 않습니다(US-I06 AC2).
BR-ORDER-2 요청 항목은 menu_id와 quantity만 받습니다. 메뉴명, 단가, 금액은 서버가 해당 매장의 Menu에서 읽어 계산합니다.
BR-ORDER-3 항목은 1줄 이상 20줄 이하이고, 각 줄의 수량은 1 이상 20 이하의 정수입니다. (Q3: A)
BR-ORDER-4 같은 menu_id가 두 번 이상 들어오면 거부합니다(VALIDATION_ERROR). 클라이언트(장바구니)가 이미 합쳐서 보냅니다.
BR-ORDER-5 다른 매장의 메뉴이거나 없는 메뉴가 있으면 주문 전체를 거부합니다(VALIDATION_ERROR). 일부만 주문되는 경우는 없습니다.
BR-ORDER-6 총 금액은 각 줄의 단가 x 수량의 합입니다. 메뉴명과 단가는 주문 시점의 값을 OrderItem에 저장하므로, 이후 Menu가 바뀌어도 기존 주문은 그대로입니다.
BR-ORDER-7 새 주문의 모든 항목은 PENDING, 주문 상태도 PENDING입니다.
BR-ORDER-8 주문 생성은 하나의 트랜잭션입니다. 세션 확보, 주문 번호 발급, 주문·항목 저장 중 하나라도 실패하면 전부 취소하고 이벤트도 보내지 않습니다.
BR-ORDER-9 활성 세션이 없으면 이 주문과 함께 새 세션을 시작합니다(started_at = 주문 시각). 활성 세션이 있으면 그 세션에 붙입니다.

BR-NO. 주문 번호

ID 규칙
BR-NO-1 주문 번호는 (매장, KST 날짜)별 카운터를 1씩 올려서 발급하고, 4자리 0 채움 형식으로 표시합니다(0001, 0002…). 9999를 넘으면 자릿수를 늘립니다(10000). (Q2: A)
BR-NO-2 날짜는 주문 시각을 KST로 바꾼 값입니다. KST 자정이 지나면 0001부터 다시 시작합니다.
BR-NO-3 카운터는 주문을 삭제해도 줄어들지 않습니다. 삭제된 번호는 재사용하지 않습니다.
BR-NO-4 번호 발급은 주문 생성 트랜잭션 안에서 합니다. 동시에 주문해도 같은 번호가 나오지 않습니다.

BR-ITEM. 메뉴 항목 상태 (Q1: A)

상태 전이 표

현재 상태 동작 결과 필요 입력
PENDING 준비 시작 PREPARING 예상 소요 시간(분) 필수
PREPARING 예상 시간 수정 PREPARING 새 소요 시간(분) 필수
PREPARING 완료 COMPLETED 없음
그 외 모든 조합 — 거부 (INVALID_STATE_TRANSITION)

예: PENDING → COMPLETED(바로 완료), COMPLETED → 다른 상태(되돌리기), COMPLETED/PENDING의 예상 시간 수정은 모두 거부합니다.

ID 규칙
BR-ITEM-1 예상 소요 시간은 1 이상 120 이하의 정수(분)입니다. 비어 있거나 범위 밖이거나 정수가 아니면 상태를 바꾸지 않고 VALIDATION_ERROR로 거부합니다. (Q3: A)
BR-ITEM-2 준비 시작: started_at = 지금, estimated_minutes = 입력값, estimated_ready_at = 지금 + 입력값(분).
BR-ITEM-3 예상 시간 수정: estimated_minutes = 새 입력값, estimated_ready_at = 지금 + 새 입력값(분). started_at은 바꾸지 않습니다.
BR-ITEM-4 완료: completed_at = 지금. estimated_ready_at과 estimated_minutes는 기록으로 남깁니다.
BR-ITEM-5 전체 준비 시작(주문 단위): 그 주문의 PENDING 항목 전체에 BR-ITEM-2를 같은 시각·같은 입력값으로 적용합니다. 이미 PREPARING/COMPLETED인 항목은 건드리지 않습니다. PENDING 항목이 하나도 없으면 거부합니다(INVALID_STATE_TRANSITION). 하나의 트랜잭션이라 일부만 바뀌지 않습니다.
BR-ITEM-6 수량이 2 이상인 항목은 줄 전체가 하나의 상태입니다. 일부 수량만 완료로 만드는 기능은 없습니다. 줄 전체를 완료 처리해야 완료입니다.
BR-ITEM-7 보관된(archived_at이 있는) 주문의 항목은 어떤 상태 변경도 할 수 없습니다(ORDER_ARCHIVED).
BR-ITEM-8 상태 변경은 관리자만 할 수 있습니다. 항목이 관리자 매장의 것이 아니면 존재하지 않는 것처럼 NOT_FOUND로 응답합니다.
BR-ITEM-9 "곧 나옵니다"(예상 시각 경과)는 서버가 상태로 저장하지 않습니다. 화면이 estimated_ready_at과 서버 시각 기준으로 판단합니다.

BR-STATUS. 주문 상태 자동 결정

ID 규칙
BR-STATUS-1 모든 항목이 PENDING이면 주문은 PENDING입니다.
BR-STATUS-2 모든 항목이 COMPLETED이면 주문은 COMPLETED입니다.
BR-STATUS-3 그 외(하나라도 PREPARING이거나, PENDING과 COMPLETED가 섞인 경우)는 PREPARING입니다.
BR-STATUS-4 주문 상태는 직접 바꿀 수 없고, 항목이 바뀔 때마다 같은 트랜잭션에서 다시 계산해 저장합니다.
BR-STATUS-5 미완료 항목 수(unfinished_item_count)는 현재 세션 주문 전체에서 COMPLETED가 아닌 항목(줄) 수입니다.

BR-DELETE. 주문 삭제

ID 규칙
BR-DELETE-1 관리자가 현재 주문(archived_at 없음)을 삭제하면 주문과 그 항목 전체가 즉시 지워집니다. 항목 상태와 관계없습니다.
BR-DELETE-2 보관된 주문은 삭제할 수 없습니다(ORDER_ARCHIVED).
BR-DELETE-3 개별 항목만 삭제하는 기능은 없습니다.
BR-DELETE-4 삭제 후 테이블 총액은 남은 현재 주문의 total_amount 합으로 다시 계산합니다.
BR-DELETE-5 삭제로 세션의 주문이 0건이 되어도 세션은 종료되지 않습니다. 다음 주문은 같은 세션에 들어갑니다. (Q6: A)
BR-DELETE-6 주문 번호 카운터는 줄이지 않습니다(BR-NO-3).

BR-SESSION. 테이블 세션과 이용 완료

ID 규칙
BR-SESSION-1 테이블 하나에 활성 세션은 최대 1개입니다. 세션 시작은 첫 주문 때만 일어납니다(BR-ORDER-9).
BR-SESSION-2 세션은 관리자의 이용 완료로만 종료됩니다. 시간 경과로 자동 종료되지 않습니다.
BR-SESSION-3 이용 완료는 하나의 트랜잭션으로 다음 두 가지를 합니다. ① 그 세션의 현재 주문 전부에 archived_at = 지금을 기록 ② 세션의 ended_at = 지금을 기록. 일부만 반영되는 경우는 없습니다.
BR-SESSION-4 주문과 항목 데이터는 지우거나 복사하지 않습니다. 항목 상태도 그대로 보존합니다(대기중/준비중이던 항목도 그 상태로 남음).
BR-SESSION-5 안 나간 메뉴(PENDING/PREPARING 항목)가 남아 있어도 이용 완료를 막지 않습니다. 확인 팝업에 unfinished_item_count를 표시하는 것은 화면의 몫입니다. (Q4: A)
BR-SESSION-6 활성 세션이 없는 테이블에 이용 완료를 요청하면 아무것도 바꾸지 않고 성공으로 응답합니다(session_id: null). 이 경우 이벤트도 보내지 않습니다.
BR-SESSION-7 이용 완료 후 현재 주문 목록과 총액은 0입니다(archived_at이 없는 주문이 없으므로). 다음 첫 주문이 새 세션을 시작합니다.
BR-SESSION-8 커밋이 실패하면 전체를 롤백하고 이벤트를 보내지 않습니다.

BR-VIEW. 조회 규칙

ID 규칙
BR-VIEW-1 태블릿의 주문 내역은 자기 테이블의 활성 세션의 현재 주문만 보여줍니다. 최신 주문이 위입니다(주문 ID 내림차순).
BR-VIEW-2 태블릿 주문 목록의 페이지 크기는 기본 20, 최대 50입니다. 다음 페이지는 마지막으로 받은 주문 ID를 cursor로 보내서 요청합니다.
BR-VIEW-3 대시보드는 매장의 모든 테이블을 보여줍니다. 각 테이블의 총액은 활성 세션의 현재 주문 total_amount 합이고, 세션이 없으면 0입니다.
BR-VIEW-4 대시보드의 recent_orders는 활성 세션의 현재 주문 중 최신 3개입니다.
BR-VIEW-5 과거 주문 내역은 해당 테이블의 보관된 주문을 최신순으로 보여줍니다. 각 주문에는 session_id와 이용 완료 시각(archived_at)이 들어갑니다.
BR-VIEW-6 과거 내역의 날짜 필터는 주문 시각(created_at)의 KST 날짜가 선택한 날짜와 같은 주문만 보여줍니다. 날짜가 없으면 전체입니다. 페이지 크기는 기본 50, 최대 100이고 cursor로 다음 페이지를 요청합니다.
BR-VIEW-7 메뉴 조회는 해당 매장의 카테고리(sort_order 순)와 그 안의 메뉴(sort_order 순)를 돌려줍니다.

BR-TABLE. 테이블 관리

ID 규칙
BR-TABLE-1 테이블 번호는 1 이상 999 이하의 정수이고 매장 안에서 유일합니다. 중복이면 DUPLICATE_TABLE_NUMBER로 거부합니다.
BR-TABLE-2 테이블 비밀번호는 4자 이상 50자 이하입니다. bcrypt 해시로 저장합니다.
BR-TABLE-3 테이블 삭제 기능은 없습니다(범위 밖).
BR-TABLE-4 테이블 등록은 SSE 이벤트를 보내지 않습니다. 대시보드는 화면을 열 때(또는 재동기화 때) 테이블 목록을 새로 받습니다.

BR-SCOPE. 데이터 접근 범위

ID 규칙
BR-SCOPE-1 모든 조회와 변경은 토큰의 store_id로 제한합니다. 다른 매장의 데이터는 존재하지 않는 것처럼 NOT_FOUND로 응답합니다.
BR-SCOPE-2 태블릿 토큰은 추가로 자기 table_id의 데이터만 다룰 수 있습니다.
BR-SCOPE-3 SSE 채널은 토큰으로 정해집니다. 관리자는 자기 매장 채널, 태블릿은 자기 테이블 채널만 구독합니다. 클라이언트가 채널을 고를 수 없습니다.

오류 응답 형식과 코드

모든 오류는 {"error": {"code": "...", "message": "...", "details": {...}}} 형식입니다.

code HTTP 발생 조건
INVALID_CREDENTIALS 401 로그인 정보 불일치
INVALID_TOKEN 401 토큰 없음, 위조, 만료, 종류 불일치
ACCOUNT_LOCKED 423 잠금 중. details.locked_until 포함
NOT_FOUND 404 없는 리소스, 다른 매장/테이블의 리소스
VALIDATION_ERROR 422 입력 형식, 범위, 중복 줄, 없는 메뉴
INVALID_STATE_TRANSITION 409 허용되지 않는 항목 상태 전이
ORDER_ARCHIVED 409 보관된 주문의 변경/삭제 시도
DUPLICATE_TABLE_NUMBER 409 중복 테이블 번호
