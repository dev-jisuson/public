Domain Entities — backend

기술에 얽매이지 않는 논리 모델입니다. 실제 컬럼 타입과 인덱스는 Code Generation에서 정합니다.

공통 규칙

  • 모든 시각은 UTC로 저장하고, 응답은 ISO 8601(Z 포함)로 내려줍니다. 화면 표시와 "하루" 기준은 한국 시간(KST, UTC+9)입니다.
  • 금액은 원 단위 정수입니다.
  • 매장 소유 엔티티는 모두 store_id를 갖고, 모든 조회는 store_id 범위 안에서만 합니다.

ER 개요

    Store ||--o{ Table : has

Text Alternative

Store 1---* AdminUser, Table, Category, Menu, DailyOrderCounter
Category 1---* Menu
Table 1---* TableSession ; Table 1---* Order
TableSession 1---* Order
Order 1---+ OrderItem ; Menu 1---* OrderItem (참조만, 스냅샷 별도 저장)
LoginAttempt : 독립 (키 = 종류 + 매장코드 + 식별자)

Store

필드 설명
id PK
code 매장 식별자. 전체에서 유일. 로그인에 사용 (예: demo)
name 매장 이름

AdminUser

필드 설명
id PK
store_id FK → Store
username 매장 안에서 유일
password_hash bcrypt 해시

LoginAttempt

로그인 실패 횟수와 잠금 상태를 저장합니다.

필드 설명
id PK
kind admin 또는 table
store_code 입력받은 매장 식별자 (존재하지 않는 값도 기록)
identifier admin이면 username, table이면 테이블 번호 문자열
fail_count 연속 실패 횟수
locked_until 잠금 해제 시각. 잠금 중이 아니면 비어 있음
updated_at 마지막 갱신 시각
  • 유일 키: (kind, store_code, identifier)

Table

필드 설명
id PK
store_id FK → Store
number 테이블 번호(정수). 매장 안에서 유일
password_hash bcrypt 해시 (태블릿 로그인용)
created_at 생성 시각

TableSession

식사 1회 단위입니다. 첫 주문 때 시작하고 관리자의 이용 완료로 끝납니다.

필드 설명
id PK
store_id FK → Store
table_id FK → Table
started_at 첫 주문 시각
ended_at 이용 완료 시각. 비어 있으면 활성 세션
  • 제약: 한 테이블에 활성 세션(ended_at 없음)은 최대 1개

Category

필드 설명
id PK
store_id FK → Store
name 카테고리 이름
sort_order 노출 순서 (오름차순)

Menu

seed로만 생성합니다. 관리 화면은 없습니다.

필드 설명
id PK
store_id FK → Store
category_id FK → Category
name 메뉴명
price 가격(원)
description 설명
image_path 정적 이미지 경로 (예: /static/images/kimchi-jjigae.svg)
sort_order 카테고리 안 노출 순서

DailyOrderCounter

주문 번호 채번용입니다. 주문을 삭제해도 번호가 재사용되지 않게 합니다.

필드 설명
store_id FK → Store
business_date KST 기준 날짜
last_no 오늘 마지막으로 발급한 번호
  • 유일 키: (store_id, business_date)

Order

필드 설명
id PK
store_id FK → Store
table_id FK → Table
session_id FK → TableSession
business_date 주문 시점의 KST 날짜
order_no 표시용 주문 번호 (0001 형식). (store_id, business_date, order_no)가 유일
total_amount 항목 합계(원). 서버가 계산
status 파생 상태: PENDING / PREPARING / COMPLETED. 항목이 바뀔 때마다 다시 계산해 저장
created_at 주문 시각
archived_at 이용 완료로 보관된 시각. 비어 있으면 현재 주문
  • "현재 주문" = archived_at이 비어 있는 주문
  • "과거 주문" = archived_at이 있는 주문. 별도 이력 테이블은 만들지 않습니다.

OrderItem

주문 줄 단위입니다. "파스타 x3"은 항목 1개이며 상태와 예상 시간도 하나만 갖습니다.

필드 설명
id PK
order_id FK → Order (삭제 시 함께 삭제)
menu_id 참조용 FK → Menu
menu_name 주문 시점 메뉴명 스냅샷
unit_price 주문 시점 단가 스냅샷
quantity 수량 (1~20)
status PENDING / PREPARING / COMPLETED
estimated_minutes 입력한 예상 소요 시간(분). 준비 시작 전에는 비어 있음
started_at 준비 시작 시각
estimated_ready_at 예상 완료 시각
completed_at 완료 처리 시각

상태 값 한글 매핑

코드 화면 표시
PENDING 대기중
PREPARING 준비중
COMPLETED 완료

응답 DTO 개요 (API 계약)

OrderItemDTO

id, menu_id, menu_name, unit_price, quantity, line_total, status, estimated_minutes, started_at, estimated_ready_at, completed_at

OrderDTO

id, order_no, table_id, table_number, session_id, status, total_amount, created_at, archived_at, items[]

TableSummaryDTO (대시보드 카드)

table_id, table_number, session_id(없으면 null), total_amount, order_count, unfinished_item_count, recent_orders[](최신 3개 OrderDTO)

TableStateDTO (태블릿 재동기화)

session_id(없으면 null), orders[](현재 세션 주문 전체), server_time

인증 응답

  • 관리자: token, expires_at
  • 태블릿: token, expires_at, store_id, table_id, table_number
