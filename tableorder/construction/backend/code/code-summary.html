Code Summary — backend

코드 위치: tableorder/backend/ (실행 방법은 backend/README.md)

범위 변경: 인증 제외 (2026-10-14, 사용자 지시 "인증 관련된건 다 빼도 돼. MVP니까")

  • 구현하지 않음: 로그인/로그아웃, JWT, 비밀번호/bcrypt, 로그인 잠금, AdminUser·LoginAttempt, 테이블 비밀번호, SSE 토큰 검증
  • 대체: X-Store-Code(생략 시 demo), X-Table-Number 헤더로 식별. SSE는 쿼리 store_code, table_number
  • 유지: 매장/테이블 범위 격리, 클라이언트가 매장·테이블·가격을 지정할 수 없음(extra=forbid, 서버 계산)
  • 설계 문서와 어긋나는 부분(갱신 필요): requirements.md FR 인증 항목, 스토리 US-C01~C03·US-A01~A03, business-rules.md BR-AUTH/BR-LOCK, component-methods.md 1·2절(security/AuthService) 및 4절 로그인 엔드포인트, 도메인 엔티티 AdminUser/LoginAttempt/Table.password_hash, ACCOUNT_LOCKED/INVALID_CREDENTIALS/INVALID_TOKEN 오류 코드. 프론트엔드는 로그인 화면 없이 구현해야 하며, 인증이 필요해지면 core/deps.py 한 곳을 토큰 검증으로 바꾸면 됩니다.
  • 보안 주의: 모든 엔드포인트가 인증 없이 열려 있습니다. 로컬/내부망 전용이며 공개 배포 금지.

구현 결정 (설계에 없던 세부)

  • SQLite: 연결마다 foreign_keys=ON, WAL, 트랜잭션을 BEGIN IMMEDIATE로 시작해 주문 번호·세션 시작 경쟁을 직렬화
  • 활성 세션 1개 제약: 부분 유니크 인덱스 uq_one_active_session_per_table
  • 서비스에 시계 주입(Clock), 이벤트는 커밋 후에만 발행
  • 이벤트 브로커: 구독자 큐 256개 초과(느린 구독자) 시 구독 종료 → 클라이언트가 재연결 후 /api/table/state 또는 대시보드로 재동기화. SSE 스트림은 aclosing으로 연결 종료 시 구독 즉시 해제
  • 과거 내역·태블릿 주문 목록은 {items, next_cursor} 형식의 커서 페이지네이션
  • 시간 입력은 StrictInt: 문자열 "7"은 422

테스트 중 발견해 고친 버그

  1. 상태 변경 직후 미완료 항목 수가 이전 값으로 계산됨 (autoflush=False) → 집계 전 flush()
  2. 이용 완료의 대량 UPDATE가 같은 세션의 캐시된 주문에 반영되지 않음 → expire_all()
  3. SSE 연결이 끊겨도 구독이 GC 전까지 남을 수 있음 → aclosing으로 즉시 해제
