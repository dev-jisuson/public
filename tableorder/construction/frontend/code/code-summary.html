Code Summary — frontend

코드 위치: tableorder/frontend/ (실행 방법은 frontend/README.md, 루트 README.md)

범위 (backend와 동일하게 인증 제외)

  • 구현하지 않음: 관리자 로그인, 토큰/만료 타이머, 401 재로그인, 로그인 잠금 안내, 테이블 비밀번호 입력/변경 → US-C03, US-A01~A03 제외
  • 축소: US-C01은 매장 코드 + 테이블 번호만 입력(서버에 존재하는지 확인 후 저장), US-A12는 테이블 번호 등록만
  • 식별: 태블릿은 X-Store-Code/X-Table-Number 헤더(SSE는 쿼리), 관리자는 VITE_STORE_CODE(기본 demo)
  • 보안 주의: 인증이 없으므로 로컬/내부망 전용

구조

경로 역할
src/shared/ types.ts(백엔드 DTO 미러), apiClient(오류 정규화), useEventStream(SSE, 지수 백오프 1→10초, 열릴 때마다 resync), serverClock(서버 시각 보정), format(원화·KST·남은 시간 판정), useNow, OrderItemStatusBadge, ui(Button/Modal/ConfirmDialog/Toast/MenuImage), toastStore
src/table/ tableConfigStore·cartStore(persist), tableOrdersStore(이벤트 반영·resync·주문 확정), tableApi, 화면 7개(설정/메뉴/장바구니/확인/성공/내역/레이아웃), TableEventBridge
src/admin/ dashboardStore(카드·강조·필터·상세 실시간 반영), adminApi, 화면(대시보드/카드/필터/상세/시간 입력/과거 내역/테이블 관리/레이아웃)
Dockerfile, nginx.conf, 루트 docker-compose.yml 빌드 → nginx, /api·/static 프록시, SSE 버퍼링 해제, SPA fallback

구현 결정

  • 항목 버튼 규칙(UI): 대기중=준비 시작 / 준비중=시간 수정·완료 / 완료=없음. 서버가 최종 검증(409)하고 화면은 오류 토스트만 띄움
  • 시간 입력 검증: 1~120 정수(서버와 동일), 틀리면 요청을 보내지 않음
  • 이용 완료 확인 팝업에 미완료 메뉴 개수 표시 (Q4)
  • 내 요청의 응답과 SSE 이벤트가 모두 같은 반영 함수를 거쳐서 어느 쪽이 먼저 와도 결과가 같음(멱등)
  • 주문 확정 중 버튼 비활성화로 중복 제출 방지(서버는 막지 않음)
  • 이용 완료/세션 변경 감지: 저장된 sessionId와 서버 session_id가 다르면 장바구니·내역 초기화 (오프라인 중 이용 완료 대응)

동작 확인 (Step 14)

  • npm run build 성공(타입 검사 포함), npm test 115 passed
  • 실제 백엔드 + Vite 개발 서버 프록시: 페이지·메뉴 API(12개)·정적 이미지 200, 주문 생성·항목 시작 후 테이블/관리자 SSE 둘 다 order.created, order_item.updated 수신
  • docker compose build 성공, docker compose up으로 nginx 경유 확인: SPA 경로(/admin, /table/history) 200, API·정적 파일 프록시, SSE 이벤트가 주문 후 약 1.5초 안에 도착(버퍼링 없음). 확인 후 down -v로 정리
  • 확인하지 못한 것: 실제 브라우저에서의 화면 렌더링/터치 조작/스타일은 확인하지 못함(브라우저 자동화 도구 없음. 테스트는 jsdom). 카운트다운·애니메이션의 실제 모습, 태블릿 해상도 레이아웃은 직접 열어서 확인 필요

알려진 사항

  • 로컬 3000번 포트를 다른 앱이 쓰고 있으면 FRONTEND_PORT로 바꿔야 함(검증 중 실제로 겹쳤음)
  • 설계 문서의 인증 관련 내용(스토리, BR-AUTH/BR-LOCK 등)은 코드와 어긋남 → backend code-summary.md에 목록

Build and Test에서 추가 수정

  • 실제 Chrome 스크린샷에서 발견: 관리자 주문 상세의 상태 배지가 늘어남(.detail-item .badge), 메뉴 그리드 auto-fill → auto-fit. 위 "확인하지 못한 것"의 브라우저 렌더링은 Build and Test의 E2E에서 확인함 (build-and-test/e2e-test-instructions.md).

UI 개선 (Build and Test 이후, 사용자 요청 "ui 개선좀 더 해봐")

  • 관리자: 카드 미리보기에 준비중 항목 중 가장 빠른 완료 예정("가장 빠른 완료 약 N분 후") / 지연("예상보다 N분 지연", 빨간색), 상단 요약줄(이용 중 테이블, 안 나간 메뉴), 빈 테이블 카드 흐리게, 넓은 화면 활용(최대 1440px)
  • 공통: 실시간 연결 상태 표시(실시간 / 연결 끊김 · 다시 연결 중). useEventStream이 상태를 반환함
  • 고객: 스크롤을 따라 카테고리 탭 강조(탭 클릭 직후 0.8초는 중간 카테고리로 깜빡이지 않게 무시), 메뉴 카드에 N개 담김 배지, 주문 완료 화면에 체크 아이콘, 애니메이션 감소 설정 존중
  • 테스트: Vitest 126개(+11), 브라우저 E2E 7개 모두 통과(카드 남은 시간·연결 배지 검증 추가)
  • 변경 중 발견: Math.floor(-0)이 -0이 되어 지연 0분 표시가 어긋날 수 있었음 → 수정
  • 주문 확인 화면/테이블 관리 목록 여백 수정(사용자 지적): ul.order-items.card에서 .order-items { padding: 0 }이 카드 여백을 덮어써 글자가 테두리에 붙어 있었음 → 전용 .line-list/.line-total로 분리, 줄 구분선, "개당 N원 / 합계"로 표시를 나눔(기존 2,500원 · 2,500원은 의미가 모호했음)

관리자 UI 개선 + 주문 완료 카운트다운 (사용자 요청)

  • 주문 완료 화면: "N초 후 메뉴 화면으로 돌아갑니다"가 5→4→3→2→1로 1초마다 줄어듦(실제 Chrome에서 확인). 바로 나가면 타이머 정리
  • 관리자 주문 상세: 항목 줄을 한 줄 레이아웃으로 정리(빈 칸 제거), "개당 N원 · 합계 N원"으로 표기 분리, 삭제 버튼을 주 버튼과 떨어뜨림
  • 시간 입력: 자주 쓰는 시간 버튼(5/10/15/20/30분), 단위 "분" 표시, 범위 안내, 값을 고치면 오류 문구 해제
  • 테이블 관리: 한 줄 폼(번호 입력 + 등록), 등록된 테이블을 칩으로 표시, 넓은 레이아웃
  • 과거 내역: 불러오는 중 표시. 대시보드 카드 버튼을 카드 아래쪽에 정렬
  • 테스트: Vitest 131개(+5), Chrome E2E 7개 통과
