Code Generation Plan — frontend

이 문서가 frontend Code Generation의 유일한 기준입니다. 승인 후 순서대로 실행하고, 끝낸 단계는 즉시 [x]로 바꿉니다.

범위 변경 반영 (backend와 동일: 인증 제외)

  • 제외: 관리자 로그인 화면, 토큰/JWT 저장, 만료 타이머, 401 재로그인, 로그인 잠금 안내, 테이블 비밀번호 입력/변경
  • 대체
    • 태블릿: 초기 설정 화면에서 매장 코드(기본 demo)와 테이블 번호만 입력해 localStorage에 저장. 이후 모든 요청에 X-Store-Code, X-Table-Number 헤더. SSE는 쿼리 store_code, table_number.
    • 관리자: 로그인 없이 /admin으로 바로 진입. 매장 코드는 환경변수 VITE_STORE_CODE(기본 demo)를 X-Store-Code로 전송.
    • 테이블 관리 화면: 테이블 번호 등록만 (비밀번호 변경 없음)
  • 영향 스토리: US-C01은 "테이블 설정"으로 축소, US-C02는 저장된 설정으로 바로 진입, US-C03·US-A01~A03 구현 제외
  • 주의: 인증이 없으므로 로컬/내부망 전용

단위 정보

  • 단위: frontend (Unit 2)
  • 코드 위치: tableorder/frontend/ (aidlc-docs/ 안에는 코드를 두지 않음)
  • 문서 위치: aidlc-docs/construction/frontend/code/ (마크다운 요약만)
  • 프로젝트 유형: Greenfield, 다중 단위
  • 기준 설계: components.md 2절, component-methods.md 4~6절, functional-design/business-logic-model.md(SSE 페이로드), backend/README.md, 실제 DTO(backend/app/schemas/dto.py)

담당 스토리

US-C01(축소), C02, C04~C16, US-A04~A15, US-I01~I05. (US-C03, US-A01~A03 제외, US-I06은 backend)

의존성과 계약

  • backend 런타임에만 의존. REST + SSE 계약: /api/table/*, /api/admin/*, /api/sse/{table,admin}, /static/images/*
  • 타입은 backend/app/schemas/dto.py를 보고 src/shared/types.ts에 직접 작성
  • 오류 형식 {"error": {"code","message","details"}}를 ApiError로 정규화

기술 선택

  • TypeScript, React 18/19, Vite, React Router, Zustand(persist), Vitest + Testing Library(jsdom)
  • 스타일: 의존성 없이 CSS 파일(CSS 변수), 터치 영역 최소 44x44px
  • 버전은 npm view로 실제 확인한 값을 package.json에 정확히 고정 (^ 없이)
  • UI 요소에 data-testid 부여 ({component}-{element-role} 규칙, 안정적인 값)
  • 모든 시각 표시는 KST. 남은 시간은 서버 sent_at/server_time 기준 시계 오차 보정 후 계산

실행 단계

A. 구조와 기반

  • Step 1. 프로젝트 구조 설정 — frontend/ : package.json(버전 고정), tsconfig*.json, vite.config.ts(dev proxy /api, /static → localhost:8000, Vitest 설정), index.html, .env.example, src/main.tsx, src/App.tsx(라우팅 /table/*, /admin/*, / → /table), 전역 CSS. npm install
  • Step 2. shared 모듈 — src/shared/ : types.ts, apiClient.ts(헤더 첨부, ApiError), useEventStream.ts(EventSource, 지수 백오프 최대 10초, 재연결 시 onResync), format.ts(원화, KST 시각, 남은 시간), clock.ts(서버-클라이언트 시계 오차 보정), UI(Button, ConfirmDialog, Modal, Toast/ToastHost)
  • Step 3. shared 단위 테스트 — format(금액/시각/남은 시간/"곧 나옵니다" 경계), apiClient(오류 정규화, 헤더), useEventStream(이벤트 라우팅, 재연결 시 resync), 시계 보정

B. 고객용 (/table/*)

  • Step 4. 고객 스토어와 API — src/table/ : tableConfigStore(persist: 매장 코드/테이블 번호), cartStore(persist, 같은 메뉴 수량 합산, 총액), tableOrdersStore(목록, 커서 로드, SSE 이벤트 반영, 세션 변경 시 초기화), tableApi
  • Step 5. 고객 스토어 단위 테스트 — 장바구니(담기/중복 합산/증감/수량 1에서 감소 시 제거/비우기/persist 복원), 주문 스토어(created/deleted/item_updated 반영, session_completed 초기화, resync 시 세션 ID 변경이면 장바구니도 비움)
  • Step 6. 고객 화면 — TableLayout(상단 바, 설정 가드), TableSetupPage, MenuPage + CategoryTabs + MenuCard(이미지 오류 시 placeholder), CartDrawer, OrderConfirmPage, OrderSuccessPage(5초 후 이동), OrderHistoryPage(무한 스크롤), OrderItemStatusBadge(카운트다운, "곧 나옵니다"), TableEventBridge(SSE, 완료 토스트, 이용 완료 시 초기화·메뉴로 이동)
  • Step 7. 고객 화면 테스트 — 메뉴 → 담기 → 주문 확정 흐름(API mock), 주문 실패 시 장바구니 유지, 빈 장바구니 주문 버튼 비활성, 상태 배지 표시, 완료 토스트

C. 관리자용 (/admin/*)

  • Step 8. 관리자 스토어와 API — src/admin/ : dashboardStore(카드, 강조 집합, 필터, 이벤트 반영, acknowledge), adminApi
  • Step 9. 관리자 스토어 단위 테스트 — order.created 반영(총액·미완료 수·최신 3개·강조), order.deleted, order_item.updated, session_completed 리셋, 필터, 강조 해제, resync
  • Step 10. 관리자 화면 — AdminLayout(내비게이션), DashboardPage(그리드, SSE, 재연결 시 재조회), TableCard, TableFilter, OrderDetailModal(항목별 버튼 규칙: 대기중=준비 시작, 준비중=시간 수정/완료, 완료=없음, 전체 준비 시작 비활성 조건, 삭제), EstimateInputDialog(1~120 정수 검증), TableHistoryModal(날짜 필터, 더 보기), TableManagementPage, 이용 완료 확인 팝업(미완료 개수 표시)
  • Step 11. 관리자 화면 테스트 — 상태 버튼 노출 규칙, 시간 입력 검증, 이용 완료 확인 팝업 문구, 주문 삭제 취소/확인

D. 문서와 배포

  • Step 12. 배포 산출물 — frontend/Dockerfile(빌드 → nginx), frontend/nginx.conf(/api, /static 프록시, SSE용 proxy_buffering off, SPA fallback), 루트 docker-compose.yml에 frontend 서비스 추가
  • Step 13. 문서 — 루트 README.md(Docker/로컬 실행, 화면 주소, 데모 데이터, 인증 없음 경고), frontend/README.md, aidlc-docs/construction/frontend/code/code-summary.md
  • Step 14. 동작 확인 — npm run build, npm test, 실제 backend 기동 후 프론트 dev 서버 프록시로 메뉴/주문/SSE 호출 확인(curl 수준), 가능하면 docker compose build 확인. 결과를 요약에 기록
