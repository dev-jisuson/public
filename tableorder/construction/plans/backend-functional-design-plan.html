Functional Design Plan — backend

목적

backend 단위의 상세 비즈니스 로직을 기술에 얽매이지 않고 정의합니다.

  • 도메인 엔티티와 관계
  • 비즈니스 규칙과 검증
  • 핵심 흐름의 상세 로직

입력 자료

  • unit-of-work.md, unit-of-work-story-map.md
  • application-design/ (components, methods, services)
  • requirements.md, stories.md

산출물 (승인 후 생성)

aidlc-docs/construction/backend/functional-design/

  • 1. domain-entities.md — 엔티티, 필드, 관계, 제약, 상태 값
  • 2. business-rules.md — 검증 규칙, 상태 전이 표, 제한 수치, 오류 조건
  • 3. business-logic-model.md — 핵심 흐름의 단계별 로직
    • 3.1 주문 생성과 세션 시작, 주문 번호 채번
    • 3.2 메뉴 항목 상태 전이와 주문 상태 결정
    • 3.3 이용 완료 (보관 표시) 와 과거 내역 조회
    • 3.4 로그인 시도 제한
    • 3.5 SSE 이벤트 페이로드 구성
  • 4. seed 데이터 정의 (매장, 계정, 테이블, 카테고리, 메뉴)
  • 5. 37개 스토리 중 backend 담당 스토리의 인수 조건과 규칙 대조

frontend 단위는 execution-plan.md에서 Functional Design을 생략하기로 했습니다.
