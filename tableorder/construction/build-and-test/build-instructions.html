Build Instructions

Prerequisites

  • Python 3.12 이상 (검증: 3.12.13), Node.js 22 이상 (검증: 25.9.0, Docker 이미지는 node:22), npm 11
  • Docker / Docker Compose (선택, 컨테이너 실행용. 검증: Docker 29.x)
  • Google Chrome (선택, 브라우저 E2E용)
  • 환경변수 (모두 선택. 기본값으로 동작)
    • backend: DATABASE_URL(기본 backend/data/tableorder.db), CORS_ORIGINS, DEFAULT_STORE_CODE
    • frontend: VITE_STORE_CODE(기본 demo), VITE_BACKEND_URL(개발 프록시 대상, 기본 http://localhost:8000)
  • 인증이 없는 MVP입니다. 로컬/내부망 전용입니다.

Build Steps

1. 의존성 설치

# backend (버전은 pyproject.toml에 고정되어 있음)
cd backend && python3.12 -m venv .venv && .venv/bin/pip install -e ".[dev]"

# frontend (package-lock.json 기준으로 정확히 설치)
cd frontend && npm ci

2. 빌드

cd frontend && npm run build        # tsc --noEmit + vite build -> frontend/dist/
# backend는 빌드 단계가 없음 (Python). 컨테이너 이미지는 아래 3번

3. Docker 이미지 빌드 (선택)

docker compose build

4. 성공 확인

  • npm run build: 오류 없이 dist/index.html, dist/assets/*.css, dist/assets/*.js 생성 (JS 약 301 kB / gzip 94 kB)
  • docker compose build: tableorder-backend, tableorder-frontend 이미지 생성
  • 허용되는 경고: pip의 새 버전 안내, 테스트 실행 시 StarletteDeprecationWarning(httpx 관련, 동작에 영향 없음)

실행

docker compose up --build            # http://localhost:3000/table , /admin , http://localhost:8000/docs
# 포트가 겹치면: FRONTEND_PORT=3100 BACKEND_PORT=8100 docker compose up --build
  • 로컬 3000번을 이미 쓰는 앱이 있으면 컨테이너가 시작되지 않습니다 (검증 중 실제로 겹쳤음).

Troubleshooting

Bind for 127.0.0.1:3000 failed: port is already allocated

  • 원인: 호스트 포트를 다른 프로세스가 사용 중
  • 해결: FRONTEND_PORT/BACKEND_PORT 환경변수로 다른 포트 지정

backend 컨테이너/서버가 종료되지 않고 오래 걸림

  • 원인: 열린 SSE 연결이 있으면 uvicorn이 연결이 닫히기를 기다림
  • 해결: --timeout-graceful-shutdown 3을 이미 적용함 (Dockerfile, README 실행 명령). 직접 실행할 때도 같은 옵션을 붙일 것

스키마를 바꾼 뒤 no such column 오류

  • 원인: 마이그레이션 도구가 없음 (MVP)
  • 해결: backend/data/tableorder.db 삭제 후 재시작, Docker는 docker compose down -v
