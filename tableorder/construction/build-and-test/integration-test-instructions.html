Integration Test Instructions

목적

backend ↔ frontend 연동과 실시간(SSE) 동작을 실제 프로세스로 확인합니다. 두 층으로 나눕니다.

  1. 서버 연동 (backend/tests_integration/): 실제 uvicorn + 실제 HTTP/SSE 클라이언트
  2. 브라우저 E2E (e2e/): 실제 Chrome으로 빌드된 프론트엔드 + 실제 backend (e2e-test-instructions.md)

1. 서버 연동 테스트

실행

cd backend
.venv/bin/python -m pytest tests_integration -q       # 약 25초, 테스트마다 새 서버·새 DB(임시 폴더)
  • 테스트가 직접 포트를 잡고 서버를 띄우고 끄므로 별도 준비가 필요 없습니다. 기본 pytest(단위)에는 포함되지 않습니다.
  • 두 번째 매장 other는 테스트가 서버 시작 전에 DB에 직접 넣습니다.

시나리오 (9개, 2026-10-14 전부 통과)

# 시나리오 스토리 확인 내용
1 주문 → 관리자·해당 태블릿 I01, NFR 2초 안에 order.created 수신, 합계·미완료 수 일치, 다른 테이블 태블릿은 무반응
2 상태 변경 → 태블릿 I02, C14, C15 준비 시작/완료/전체 시작 이벤트, 예상 시각 포함, 전체 시작은 이벤트 1회, 다른 테이블 무반응
3 이용 완료 → 태블릿 초기화 I03, A14 table.session_completed 2초 안, 상태 API 비어 있음, 대시보드 0원, 과거 내역에 항목 상태 보존, 다음 주문은 새 세션·번호 이어짐
4 주문 삭제 I04, A13 order.deleted, 총액 재계산, 삭제된 번호 재사용 안 함
5 재연결 I05 새로 연결한 스트림은 지난 이벤트를 재전송하지 않음, 상태 API가 정확한 현재 상태를 돌려줌
6 매장 격리 I06 다른 매장 헤더로 조회/삭제/상태 변경/이용 완료/내역 모두 404, 다른 매장 메뉴로 주문 거부(422), 없는 매장 SSE 404, 다른 매장 스트림 무반응
7 동시 주문 36건 (12 스레드) BR-NO-4 주문 번호 0001~0036 중복·누락 없음, 합계 일치
8 같은 항목을 8개 동시에 준비 시작 동시성 정확히 1개만 200, 나머지 409
9 열린 SSE가 있는 채로 종료(SIGTERM) 운영 5초 이내 종료 (실측 약 2.2초)

정리

테스트가 임시 폴더와 프로세스를 직접 정리합니다. 수동 정리 불필요.

2. Docker 통합 확인 (수동, 2026-10-14 수행)

FRONTEND_PORT=3100 BACKEND_PORT=8100 docker compose up -d --build
curl localhost:3100/api/health                         # nginx 경유 API
curl -I localhost:3100/admin                           # SPA fallback (200)
curl -N "localhost:3100/api/sse/admin?store_code=demo" # 다른 터미널에서 주문하면 이벤트가 바로 도착해야 함 (버퍼링 없음)
docker compose stop backend                            # 열린 SSE가 있어도 약 4초 안에 정지
FRONTEND_PORT=3100 BACKEND_PORT=8100 docker compose down -v
  • 결과: 모두 정상. nginx 경유 SSE 이벤트가 주문 후 1.5초 안에 도착, backend 컨테이너 정지 4초.
