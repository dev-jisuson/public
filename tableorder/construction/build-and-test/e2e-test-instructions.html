End-to-End (Browser) Test Instructions

목적

실제 Google Chrome으로 빌드된 프론트엔드 + 실제 backend를 사용해, 두 대의 태블릿(1번, 2번 테이블)과 관리자 화면이 함께 도는 전체 흐름을 확인합니다. 단위 테스트(jsdom)가 잡지 못하는 렌더링·터치 영역·실제 SSE 재연결을 확인합니다.

준비

  • 시스템에 Google Chrome 설치 (브라우저를 따로 내려받지 않습니다. channel: 'chrome' 사용)
  • backend/.venv가 만들어져 있어야 합니다 (build-instructions 1번)
cd e2e && npm install

실행

cd e2e && npx playwright test        # 약 25초
  • Playwright가 직접 backend(포트 8010, 매번 새 임시 DB)와 npm run build + vite preview(포트 5174)를 띄우고 끝나면 내립니다. 3000/8000번 포트를 쓰지 않습니다.
  • 스크린샷이 e2e/screenshots/에 저장됩니다 (매 실행 덮어씀). 실패하면 e2e/test-results/에 trace가 남습니다 (npx playwright show-trace <trace.zip>).

시나리오 (7개, 2026-10-14 전부 통과)

# 내용 실측
1 설정 전에는 설정 화면 → 테이블 번호 입력 → 메뉴 12개와 이미지 정상 로드(placeholder 대체 0건). 화면의 모든 버튼·탭이 44x44px 이상
2 장바구니 담기·합산·총액, 새로고침 후 유지, 주문 확정 전에는 서버로 쓰기 요청 0건
3 주문 확정 → 확인 화면 → 주문 번호 0001 → 5초 후 메뉴 복귀, 장바구니 비워짐 → 관리자 화면에 신규 주문 강조 주문→관리자 반영 42~85ms
4 관리자 상세에서 대기중 항목엔 완료 버튼 없음, 잘못된 시간(0) 거부, 15분으로 준비 시작 → 태블릿에 "준비중 · 약 15분 남음". 태블릿이 메뉴 화면에 있어도 완료 시 토스트, 2번 테이블 태블릿엔 토스트 없음, 완료 항목엔 버튼 없음 준비 시작→태블릿 57ms
5 네트워크 단절(오프라인) 동안 일어난 상태 변경과 새 주문이 복구 후 자동 반영 복구 후 약 8초 (백오프 최대 10초)
6 이용 완료: 확인 팝업에 "아직 나가지 않은 메뉴 N개", 취소하면 변화 없음, 확인하면 카드 0원·태블릿 장바구니와 내역 초기화(설정은 유지)·과거 내역에 2건 표시·다음 주문은 새 세션(번호 0003) 이용 완료→태블릿 61ms
7 주문 삭제(취소/확인), 테이블 등록(중복 오류, 7번 등록 후 대시보드에 카드 추가)

이 단계에서 E2E가 찾아 고친 문제

  • 스크린샷에서 발견: 관리자 주문 상세의 상태 배지가 세로로 늘어난 알약 모양 → align-self 지정
  • 스크린샷에서 발견: 메뉴 카드가 3개뿐인 카테고리에서 오른쪽이 비는 레이아웃 → auto-fit으로 변경(카드가 폭을 채움)
  • (jsdom 단위 테스트로는 둘 다 발견할 수 없었음)

한계

  • 데스크톱 Chrome에서 태블릿 크기(1024x768)·터치 에뮬레이션으로 확인했습니다. 실제 태블릿 기기, Safari/Firefox, 가로·세로 회전은 확인하지 않았습니다.
  • 카운트다운이 시간에 따라 줄어드는 모습과 "곧 나옵니다" 전환은 단위 테스트(가짜 시계)로 확인했고 브라우저에서 15분을 기다리지는 않았습니다.
