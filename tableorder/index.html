테이블오더 — AI-DLC 산출물

AI-DLC로 태블릿 주문(고객) + 관리자 화면 MVP를 만들면서 생긴 문서 전체입니다. 코드는 이 저장소에 포함하지 않았습니다. AI-DLC 소개와 설치 방법은 저장소 README를 참고하세요.

구성

경로 내용
input/ 처음 주어진 원본 요구사항 (table-order-requirements.md, constraints.md)
inception/requirements/ 요구사항 분석: AI의 질문 3세트(총 27문항)와 답변, 정리된 requirements.md
inception/user-stories/ 페르소나, 스토리 37개 (Given/When/Then)
inception/application-design/ 컴포넌트, 서비스, 메서드, 유닛(backend, frontend) 정의와 의존성
inception/plans/ 워크플로우 실행 계획, 단계별 계획서와 질문
construction/backend/functional-design/ 도메인 엔티티, 비즈니스 규칙, 비즈니스 로직 모델
construction/plans/ 기능 설계 계획, 유닛별 코드 생성 계획 (체크박스 진행 기록)
construction/backend/code/, construction/frontend/code/ 코드 요약 (구조, 결정, 테스트, 검증 결과)
construction/build-and-test/ 빌드·단위·연동·성능·E2E 테스트 안내와 결과 요약

audit.md 전체 진행 기록 (사용자 입력 원문, 승인 시각, AI 응답)

한눈에 보기

  • 소요 시간: 2026-10-14 11:36 ~ 14:38 (약 3시간, 11:54–13:07 기록 공백 약 1시간 10분 포함). Build and Test 승인까지 기준이며, 이후 UI 개선(같은 날 15:25까지)과 실행 환경 준비(10-16) 기록은 audit.md 끝부분에 있음
  • 실행 단계: Workspace Detection → Requirements Analysis → User Stories → Workflow Planning → Application Design → Units Generation → Functional Design(backend) → Code Generation → Build and Test
  • 건너뛴 단계: Reverse Engineering(greenfield), NFR Requirements, NFR Design, Infrastructure Design, Operations(placeholder)
  • Unit 2개: backend(FastAPI + SQLite + SSE), frontend(React + Vite, 고객 /table + 관리자 /admin)
  • 테스트: backend pytest 73, frontend Vitest 115 (이후 UI 개선 후 131), integration 9, 실제 Chrome E2E 7 통과
  • 성능: 관리자 구독 50·주문 200건에서 PASS (최대 658ms). 구독 200·주문 500건·동시 20에서는 최대 지연 2,218ms로 2초 기준 FAIL (SQLite 쓰기 직렬화, 튜닝하지 않음)
  • 범위 변경: Code Generation 중 사용자 지시로 인증 제외 (설계 문서의 인증 관련 내용은 코드와 다름. construction/backend/code/code-summary.md 참고)

건너뛴 단계는 어떤 경우에 필요한가

AI-DLC는 모든 단계가 강제가 아니라 상황에 따라 조건부로 실행된다. 이번 프로젝트가 건너뛴 단계들은 아래와 같은 상황이면 넣어야 한다.

단계 이번 생략 사유 넣어야 하는 경우 (예시)
Reverse Engineering 그린필드 — 기존 코드 없음 레거시 시스템에 신규 기능 추가, 유지보수 중인 모놀리스 리팩토링
NFR Requirements 기술 스택과 성능 목표가 이미 결정 운영 트래픽을 받는 프로덕션 서비스, 성능/가용성 SLA가 중요한 B2B
NFR Design NFR Requirements를 생략해서 자동 생략 보안이 중요한 금융·의료, 캐싱·큐 등 비기능 아키텍처가 필요한 서비스
Infrastructure Design 로컬 전용 MVP AWS·GCP 등에 실제 배포, 멀티 리전·CDN·오토스케일링 필요
Operations (v1) v1에서는 아직 placeholder — (v2에서 본격화 예정)

상세 사유는 inception/plans/execution-plan.md에 적혀 있다.

산출물 읽을 때 참고

산출물은 AI-DLC 진행 중 생성된 그대로 두었다. 그래서 아래 사항은 문서 안에서 고치지 않고 여기에만 적는다.

  • 경로 이름: 원래 프로젝트의 aidlc-docs/가 이 저장소의 docs/tableorder/이고, requirements/가 input/이다. 산출물 본문에는 원래 경로가 그대로 적혀 있다.
  • 시간 표기: audit.md·aidlc-state.md 앞부분의 ...Z 시각은 실제로는 한국 시간(KST)이다. Code Generation 계획 승인(14:01) 이후 항목은 +09:00으로 표기되어 있다.
  • 인증 제외의 영향: 아래 문서는 인증(로그인·JWT·잠금) 설계를 그대로 담고 있다. 실제 코드는 매장 코드·테이블 번호 헤더로 식별하고 로그인이 없다.
    • requirements.md
    • stories.md의 US-C01–C03, US-A01–A03, US-A12(테이블 비밀번호), US-I06(관리자 토큰)
    • inception/application-design/
    • construction/backend/functional-design/
  • 작성 시점 기록: 다음 문서에는 작성 당시 상태가 남아 있다.
    • execution-plan.md의 다이어그램·체크박스는 Workflow Planning 진행 시점 기준이다(이후 단계가 미완료로 보임).
    • aidlc-state.md 상단의 Current Stage 등 일부 필드는 마지막 단계에서 갱신되지 않았다.
