User Stories

작성 기준

  • 구성: Epic 단위. 고객 Epic(E1~E5), 관리자 Epic(E6~E9), 연동 Epic(E10)
  • 스토리 크기: 화면/동작 단위
  • 인수 조건: Given / When / Then. 정상 흐름과 주요 예외 흐름 포함
  • 우선순위: 표시하지 않음. 모두 MVP 필수
  • 추적: 각 스토리에 requirements.md의 FR 번호 표기
  • 페르소나: P1 = 테이블 고객, P2 = 매장 운영자 (personas.md 참고)

고객 Epic

E1. 태블릿 설정 및 자동 로그인

US-C01. 태블릿 초기 설정

  • Persona: P2 (태블릿 설정자) / FR: FR-C1
  • Story: 매장 운영자로서, 태블릿에 매장 식별자/테이블 번호/테이블 비밀번호를 한 번만 입력하고 싶다. 그래야 손님이 로그인 없이 바로 주문할 수 있다.

인수 조건

  • AC1 (정상)
    • Given: 로그인 정보가 저장되지 않은 태블릿
    • When: 올바른 매장 식별자, 테이블 번호, 비밀번호를 입력하고 저장
    • Then: 16시간 토큰이 발급되고, 로그인 정보와 토큰이 localStorage에 저장되며, 메뉴 화면이 표시된다
  • AC2 (예외)
    • Given: 초기 설정 화면
    • When: 존재하지 않는 매장/테이블 또는 틀린 비밀번호를 입력
    • Then: "매장 정보 또는 비밀번호가 올바르지 않습니다" 메시지가 표시되고, 아무것도 저장되지 않는다
  • AC3 (예외)
    • Given: 같은 태블릿에서 연속 5회 로그인에 실패
    • When: 6번째 시도
    • Then: 15분 동안 로그인이 차단되고, 차단 안내 메시지가 표시된다

US-C02. 자동 로그인

  • Persona: P1 / FR: FR-C1
  • Story: 손님으로서, 태블릿을 열면 별도 로그인 없이 바로 메뉴를 보고 싶다.

인수 조건

  • AC1 (정상)
    • Given: 초기 설정이 완료된 태블릿
    • When: 브라우저를 새로 열거나 새로고침
    • Then: 로그인 화면 없이 메뉴 화면이 바로 표시된다

US-C03. 토큰 만료 시 자동 재로그인

  • Persona: P1 / FR: FR-C1
  • Story: 손님으로서, 태블릿 인증이 만료되어도 주문 중에 끊기지 않기를 원한다.

인수 조건

  • AC1 (정상)
    • Given: 저장된 토큰이 16시간이 지나 만료됨
    • When: 화면을 열거나 API 요청이 인증 만료로 거부됨
    • Then: 저장된 매장ID/테이블번호/비밀번호로 자동 재로그인하고, 원래 요청을 다시 수행한다. 고객에게는 에러가 보이지 않는다
  • AC2 (예외)
    • Given: 관리자가 테이블 비밀번호를 변경함
    • When: 자동 재로그인 시도
    • Then: 재로그인에 실패하고, 초기 설정 화면으로 이동한다

E2. 메뉴 탐색

US-C04. 카테고리별 메뉴 카드 보기

  • Persona: P1 / FR: FR-C2
  • Story: 손님으로서, 카테고리별로 정리된 메뉴를 사진과 함께 보고 싶다. 그래야 먹고 싶은 메뉴를 쉽게 고를 수 있다.

인수 조건

  • AC1 (정상)
    • Given: 자동 로그인된 태블릿
    • When: 메뉴 화면(기본 화면)이 열림
    • Then: seed 데이터의 카테고리와 메뉴가 정해진 노출 순서대로 카드 형태로 표시된다. 카드에는 메뉴명, 가격, 설명, 이미지가 있다
  • AC2 (정상)
    • Given: 메뉴 카드
    • When: 화면에 표시됨
    • Then: 모든 터치 가능한 요소는 최소 44x44px이다
  • AC3 (예외)
    • Given: 이미지 파일을 불러오지 못함
    • When: 메뉴 카드가 표시됨
    • Then: 기본 플레이스홀더 이미지가 대신 표시된다

US-C05. 카테고리 빠른 이동

  • Persona: P1 / FR: FR-C2
  • Story: 손님으로서, 카테고리 탭을 눌러 원하는 카테고리로 바로 이동하고 싶다.

인수 조건

  • AC1 (정상)
    • Given: 메뉴 화면
    • When: 카테고리 탭(예: "음료")을 누름
    • Then: 해당 카테고리 메뉴 영역으로 바로 이동하고, 선택한 탭이 강조된다

E3. 장바구니

US-C06. 장바구니에 메뉴 담기

  • Persona: P1 / FR: FR-C3
  • Story: 손님으로서, 고른 메뉴를 장바구니에 담고 총 금액을 바로 확인하고 싶다.

인수 조건

  • AC1 (정상)
    • Given: 장바구니가 비어 있음
    • When: 메뉴 카드의 "담기"를 누름
    • Then: 해당 메뉴가 수량 1로 장바구니에 추가되고, 장바구니 개수와 총 금액이 즉시 갱신된다
  • AC2 (정상)
    • Given: 이미 장바구니에 있는 메뉴
    • When: 같은 메뉴를 다시 "담기"
    • Then: 새 항목이 생기지 않고 수량이 1 증가한다

US-C07. 수량 조절 및 항목 삭제

  • Persona: P1 / FR: FR-C3
  • Story: 손님으로서, 장바구니에서 수량을 바꾸거나 메뉴를 뺄 수 있기를 원한다.

인수 조건

  • AC1 (정상)
    • Given: 수량 2인 항목
    • When: "+" 또는 "−"를 누름
    • Then: 수량이 1 증가/감소하고, 총 금액이 즉시 다시 계산된다
  • AC2 (정상)
    • Given: 수량 1인 항목
    • When: "−"를 누르거나 "삭제"를 누름
    • Then: 항목이 장바구니에서 제거된다

US-C08. 장바구니 비우기

  • Persona: P1 / FR: FR-C3
  • Story: 손님으로서, 장바구니를 한 번에 비우고 싶다.

인수 조건

  • AC1 (정상)
    • Given: 항목이 여러 개인 장바구니
    • When: "비우기"를 누름
    • Then: 모든 항목이 제거되고 총 금액이 0원이 된다

US-C09. 새로고침해도 장바구니 유지

  • Persona: P1 / FR: FR-C3
  • Story: 손님으로서, 실수로 화면을 새로고침해도 담아둔 메뉴가 사라지지 않기를 원한다.

인수 조건

  • AC1 (정상)
    • Given: 항목 3개가 담긴 장바구니
    • When: 페이지를 새로고침하거나 브라우저를 다시 염
    • Then: 같은 항목과 수량이 그대로 남아 있다
  • AC2 (정상)
    • Given: 장바구니를 수정함
    • When: 수정할 때마다
    • Then: 서버로는 아무 요청도 보내지 않는다. 주문 확정 시에만 서버로 전송된다

E4. 주문하기

US-C10. 주문 내역 확인 및 확정

  • Persona: P1 / FR: FR-C4
  • Story: 손님으로서, 주문하기 전에 담은 메뉴와 총액을 최종 확인하고 주문을 확정하고 싶다.

인수 조건

  • AC1 (정상)
    • Given: 항목이 있는 장바구니
    • When: "주문하기"를 누름
    • Then: 메뉴명, 수량, 단가, 총액이 있는 확인 화면이 표시된다
  • AC2 (정상)
    • Given: 확인 화면
    • When: "주문 확정"을 누름
    • Then: 매장 ID, 테이블 ID, 메뉴 목록, 총액, 테이블 세션 ID로 주문이 생성된다
  • AC3 (정상)
    • Given: 해당 테이블에 진행 중인 테이블 세션이 없음
    • When: 주문 확정
    • Then: 새 테이블 세션이 시작되고 주문이 그 세션에 연결된다
  • AC4 (예외)
    • Given: 장바구니가 비어 있음
    • When: 화면 표시
    • Then: "주문하기" 버튼이 비활성화된다

US-C11. 주문 성공 안내 후 메뉴 화면 복귀

  • Persona: P1 / FR: FR-C4
  • Story: 손님으로서, 주문이 제대로 들어갔다는 것을 주문 번호로 확인하고 싶다.

인수 조건

  • AC1 (정상)
    • Given: 주문이 성공함
    • When: 서버가 주문 번호를 응답
    • Then: 주문 번호(예: "0007")가 표시되고, 장바구니가 비워지며, 5초 후 메뉴 화면으로 자동 이동한다

US-C12. 주문 실패 처리

  • Persona: P1 / FR: FR-C4
  • Story: 손님으로서, 주문이 실패해도 담아둔 메뉴를 다시 담지 않아도 되기를 원한다.

인수 조건

  • AC1 (예외)
    • Given: 서버 오류 또는 네트워크 끊김
    • When: 주문 확정
    • Then: 에러 메시지가 표시되고, 장바구니는 그대로 유지되며, 다시 시도할 수 있다

E5. 주문 내역 및 진행 상황

US-C13. 현재 식사 중 주문 내역 보기

  • Persona: P1 / FR: FR-C5
  • Story: 손님으로서, 이번 식사에서 지금까지 주문한 내역과 금액을 보고 싶다.

인수 조건

  • AC1 (정상)
    • Given: 현재 테이블 세션에 주문 3건
    • When: "주문 내역"을 엶
    • Then: 3건이 최신순으로 표시된다. 각 주문에는 주문 번호, 시각, 메뉴/수량, 금액, 주문 상태가 있다
  • AC2 (정상)
    • Given: 이전 손님의 이용 완료 처리된 주문이 있음
    • When: 주문 내역을 엶
    • Then: 이전 세션의 주문은 표시되지 않는다
  • AC3 (정상)
    • Given: 주문이 한 페이지 분량보다 많음
    • When: 목록 끝까지 스크롤
    • Then: 다음 주문들이 이어서 로드된다

US-C14. 메뉴 항목별 상태와 남은 시간 보기

  • Persona: P1 / FR: FR-C5
  • Story: 손님으로서, 주문한 메뉴마다 준비 상태와 나오기까지 남은 시간을 보고 싶다.

인수 조건

  • AC1 (정상)
    • Given: 대기중 항목
    • When: 주문 내역을 봄
    • Then: "대기중"으로 표시되고, 남은 시간은 표시되지 않는다
  • AC2 (정상)
    • Given: 예상 완료 시각이 12분 뒤인 준비중 항목
    • When: 주문 내역을 봄
    • Then: "준비중 · 약 12분 남음"으로 표시되고, 남은 시간은 화면에서 계속 줄어든다
  • AC3 (정상)
    • Given: 예상 완료 시각이 지났지만 아직 준비중인 항목
    • When: 주문 내역을 봄
    • Then: "곧 나옵니다"로 표시된다
  • AC4 (정상)
    • Given: 항목 상태 조합
    • When: 주문 상태를 표시
    • Then: 모든 항목이 대기중이면 "대기중", 모두 완료면 "완료", 그 외에는 "준비중"으로 표시된다

US-C15. 진행 상황 실시간 갱신

  • Persona: P1 / FR: FR-C5
  • Story: 손님으로서, 새로고침하지 않아도 준비 상태와 남은 시간이 자동으로 바뀌기를 원한다.

인수 조건

  • AC1 (정상)
    • Given: 주문 내역 화면이 열려 있음
    • When: 관리자가 항목 상태를 바꾸거나 예상 시간을 수정
    • Then: 2초 이내에 화면에 반영된다 (SSE)

US-C16. 완료 알림 배너

  • Persona: P1 / FR: FR-C6
  • Story: 손님으로서, 메뉴 화면을 보고 있어도 내 메뉴가 곧 나온다는 것을 알고 싶다.

인수 조건

  • AC1 (정상)
    • Given: 손님이 메뉴 화면(또는 아무 화면)을 보고 있음
    • When: 이 테이블의 메뉴 항목이 "완료"로 바뀜
    • Then: 2초 이내에 "○○ 메뉴가 곧 서빙됩니다" 배너/토스트가 화면 위쪽에 표시된다
  • AC2 (정상)

    • Given: 장바구니에 항목이 남은 3번 테이블 태블릿
    • When: 관리자가 3번 테이블 이용 완료
    • Then: 2초 이내에 태블릿의 장바구니와 주문 내역이 비워지고, 메뉴 화면으로 이동한다
  • AC2 (정상)
    • Given: 초기화된 태블릿
    • When: 상태 확인
    • Then: 태블릿 로그인 정보는 유지되어 바로 다음 주문이 가능하다
  • AC3 (예외)
    • Given: 이용 완료 시점에 태블릿이 꺼져 있었음
    • When: 태블릿을 다시 켜고 접속
    • Then: 서버의 현재 세션 상태와 맞춰서 장바구니와 주문 내역이 비워진다

US-I04. 주문 삭제 → 태블릿 반영

  • Persona: P1, P2 / FR: FR-A4, FR-C5
  • Story: 운영자가 주문을 삭제하면 손님 화면의 주문 내역에서도 사라지기를 원한다.

인수 조건

  • AC1 (정상)
    • Given: 주문 내역을 보고 있는 태블릿
    • When: 관리자가 그 테이블의 주문을 삭제
    • Then: 2초 이내에 해당 주문이 태블릿 주문 내역에서 사라진다

US-I05. 연결 끊김 후 상태 동기화

  • Persona: P1, P2 / FR: NFR 신뢰성
  • Story: 손님과 운영자로서, 네트워크가 잠시 끊겼다 돌아와도 최신 상태를 보고 싶다.

인수 조건

  • AC1 (예외)
    • Given: SSE 연결이 끊긴 관리자 화면 또는 태블릿
    • When: 네트워크가 복구됨
    • Then: 자동으로 다시 연결하고, 현재 상태 전체를 다시 조회해서 끊긴 동안 놓친 변경을 반영한다

US-I06. 매장 간 데이터 분리

  • Persona: P1, P2 / FR: NFR 보안
  • Story: 운영자로서, 다른 매장 사람이 우리 매장 주문을 보거나 바꿀 수 없기를 원한다.

인수 조건

  • AC1 (예외)
    • Given: A 매장 관리자 토큰
    • When: B 매장의 주문/테이블 API를 호출하거나 B 매장 SSE를 구독
    • Then: 접근이 거부된다
  • AC2 (예외)
    • Given: 3번 테이블 태블릿 토큰
    • When: 다른 테이블 ID로 주문을 생성하거나 다른 테이블 주문 내역을 조회
    • Then: 접근이 거부된다

INVEST 점검 결과

  • Independent: 대부분 독립적입니다. 연동 Epic(E10)은 고객/관리자 스토리에 의존하지만, 검증 대상(실시간 전달)이 따로 있어서 별도 스토리로 유지했습니다.
  • Negotiable: UI 세부 사항(배너 문구, 애니메이션 방식)은 고정하지 않았습니다.
  • Valuable: 모든 스토리에 페르소나 관점의 가치를 명시했습니다.
  • Estimable / Small: 화면/동작 단위로 나눴습니다. 가장 큰 스토리는 US-A14(이용 완료, 트랜잭션 처리)입니다.
  • Testable: 모든 스토리에 Given/When/Then 인수 조건이 있습니다. 시간 기준(2초, 5초, 16시간, 15분)은 수치로 명시했습니다.
