Story Generation Plan

목적

requirements.md의 기능 요구사항(FR-C1~C7, FR-A1~A4)을 사용자 중심 스토리와 인수 조건으로 바꿉니다.

입력 자료

  • aidlc-docs/inception/requirements/requirements.md (승인됨)
  • aidlc-docs/inception/plans/user-stories-assessment.md

스토리 분해 방식 옵션 (Question 1에서 선택)

방식 설명 장점 단점
User Journey-Based 사용 흐름 순서대로 구성 (착석 → 주문 → 대기 → 서빙 → 이용 완료) 고객/관리자 연동 흐름이 잘 보임 같은 기능이 여러 여정에 흩어질 수 있음
Feature-Based 기능 단위로 구성 (메뉴, 장바구니, 주문, 대시보드…) 요구사항 FR 번호와 1:1 대응, 추적 쉬움 기능 간 연동 시나리오가 덜 보임
Persona-Based 고객 스토리 / 관리자 스토리로 나눔 화면(앱) 단위 구현과 잘 맞음 연동 스토리가 양쪽에 중복될 수 있음
Epic-Based Epic(큰 기능 묶음) 아래에 세부 스토리 계층 구조로 범위 파악 쉬움 문서가 길어짐

실행 체크리스트 (Part 2 - Generation)

  • 1. 페르소나 정의 → aidlc-docs/inception/user-stories/personas.md
    • 1.1 고객 페르소나 (목표, 상황, 불편 요소)
    • 1.2 관리자 페르소나 (목표, 상황, 불편 요소)
  • 2. 승인된 분해 방식에 따라 Epic/그룹 구조 확정
  • 3. 고객 스토리 작성 (FR-C1 ~ FR-C7)
  • 4. 관리자 스토리 작성 (FR-A1 ~ FR-A4)
  • 5. 고객↔관리자 실시간 연동 스토리 및 인수 조건 작성 (주문 → 상태 변경 → 완료 알림 → 이용 완료 초기화)
  • 6. 각 스토리에 인수 조건 작성 (승인된 형식 사용)
  • 7. 각 스토리에 FR 번호 추적 표시 및 페르소나 매핑
  • 8. INVEST 기준 점검 (Independent, Negotiable, Valuable, Estimable, Small, Testable)
  • 9. aidlc-docs/inception/user-stories/stories.md 저장
