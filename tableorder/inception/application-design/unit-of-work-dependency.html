Unit of Work Dependency

의존 매트릭스

행이 열에 의존하면 ●로 표시합니다.

의존하는 쪽 \ 대상 backend frontend
backend —
frontend ● (런타임: REST + SSE 계약) —
  • 의존 방향은 frontend → backend 한쪽뿐이라 순환이 없습니다.
  • 빌드할 때는 서로 의존하지 않습니다. 각자 따로 빌드하고 테스트할 수 있습니다.

통합 계약

계약 정의 위치 소유 단위
REST 엔드포인트 20개 component-methods.md 4절 backend
SSE 이벤트 4종과 채널 규칙 component-methods.md 5절 backend
요청/응답 스키마 backend/app/schemas/ (Pydantic) backend
TypeScript 타입 (사본) frontend/src/shared/types.ts frontend. backend 스키마와 일치해야 함
인증 방식 Authorization: Bearer / SSE는 ?token= backend
정적 이미지 경로 /static/images/{file} backend
프록시 규칙 /api/*, /static/* → backend frontend (vite.config.ts, nginx.conf)
  • 계약 변경 규칙: backend 스키마를 바꾸면 같은 작업에서 types.ts도 고칩니다. 바뀐 내용은 Code Generation 요약에 적습니다.

구현 순서

  1. backend
    1. Functional Design
    2. Code Generation
    3. pytest로 계약 확정
  2. frontend: Code Generation (확정된 backend 계약을 기준으로 함)
  3. Build and Test
    • 양쪽 빌드와 테스트
    • Docker Compose 통합 실행
    • 연동 시나리오(US-I01~I06) 확인

통합 검증 지점

시점 검증 내용
backend Code Generation 완료 API 테스트로 엔드포인트와 SSE 이벤트 계약 검증
frontend Code Generation 완료 실제 backend 대상으로 로그인 → 주문 → 상태 변경 → 이용 완료 흐름 확인
Build and Test Docker Compose로 함께 실행, 연동 스토리 6개의 인수 조건 확인
