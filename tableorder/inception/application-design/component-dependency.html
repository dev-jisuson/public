Component Dependency

1. 계층 의존 규칙

  • 의존 방향은 위에서 아래로만 흐릅니다.
    • 백엔드: api → services → repositories → models
    • core는 모든 계층이 사용할 수 있습니다.
  • 금지되는 의존
    • repositories는 services를 참조하지 않습니다.
    • services는 FastAPI(Request, HTTPException)를 참조하지 않습니다.
  • 이벤트 흐름: services가 EventPublisher를 호출하고, EventPublisher가 EventBroker에 발행합니다. 구독은 sse_router가 EventBroker에 직접 합니다.
  • 프론트엔드 의존 방향: pages/components → stores → api → shared/apiClient
    • 고객용 table/과 관리자용 admin/은 서로 참조하지 않고, shared/만 함께 씁니다.

2. 백엔드 서비스 의존 매트릭스

순환 의존은 없습니다. OrderService가 TableSessionService를 사용하지만, 반대 방향의 참조는 없습니다.

3. 통신 패턴

구간 방식 비고
프론트엔드 → 백엔드 REST (JSON over HTTP) Authorization: Bearer 헤더
백엔드 → 프론트엔드 SSE (text/event-stream) 쿼리 토큰 인증, 15초 ping, 재연결 시 전체 상태 재조회
서비스 → SSE 구독자 메모리 내 Pub/Sub (asyncio 큐) 서버 프로세스 1개 전제. EventBroker 인터페이스로 교체 가능
백엔드 → DB SQLAlchemy 2.0 → SQLite 파일 요청 단위 세션
태블릿 상태 저장 localStorage (Zustand persist) 로그인 정보, 장바구니
관리자 상태 저장 localStorage (Zustand persist) JWT, 만료 시각

5. 대표 시나리오 시퀀스: 주문부터 이용 완료까지

sequenceDiagram
    participant T as Tablet
    participant API as Backend
    participant DB as SQLite
    participant A as Admin

    T->>API: POST /api/table/orders
    API->>DB: session get_or_start, insert order
    API-->>T: 201 OrderDTO
    API--)A: SSE order.created
    A->>API: POST /api/admin/order-items/ID/start (15)
    API->>DB: status PREPARING, estimated_ready_at
    API--)T: SSE order_item.updated
    A->>API: POST /api/admin/order-items/ID/complete
    API->>DB: status COMPLETED
    API--)T: SSE order_item.updated (toast)
    A->>API: POST /api/admin/tables/ID/complete-session
    API->>DB: set archived_at on orders, close session
    API--)T: SSE table.session_completed (reset cart)
    API--)A: SSE table.session_completed (card reset)

Text Alternative

1. Tablet  -> Backend : 주문 생성 -> DB 저장 -> Tablet에 OrderDTO 응답 -> Admin에 order.created
2. Admin   -> Backend : 항목 준비 시작(15분) -> DB 갱신 -> Tablet에 order_item.updated
3. Admin   -> Backend : 항목 완료 -> DB 갱신 -> Tablet에 order_item.updated (완료 토스트)
4. Admin   -> Backend : 이용 완료 -> 주문 보관 표시, 세션 종료 -> Tablet/Admin에 table.session_completed
← 이전서비스다음 →유닛 계획 (질문 3)
