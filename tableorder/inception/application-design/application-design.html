Application Design (통합본)

이 문서는 아래 4개 문서를 하나로 합친 통합본입니다. 수정은 개별 문서에서 하고, 이 통합본은 다시 생성합니다.

  • components.md
  • component-methods.md
  • services.md
  • component-dependency.md

Components

설계 결정 요약 (application-design-plan.md 답변)

항목 결정
프론트엔드 React+Vite 앱 1개. /table/* 고객용, /admin/* 관리자용
백엔드 구조 계층형: router → service → repository
DB 접근 SQLAlchemy 2.0 (SQLite)
SSE 전달 프로세스 내부 메모리 브로커(asyncio 큐). EventBroker 인터페이스로 분리. 서버는 프로세스 1개로 실행
SSE 페이로드 변경된 데이터를 이벤트에 포함. 재연결 시에만 전체 상태를 다시 조회
SSE 인증 토큰을 쿼리 파라미터로 전달 (?token=)
프론트 상태 관리 Zustand (+ persist로 localStorage 저장)
저장소 구조 backend/, frontend/, 루트 docker-compose.yml

1. 백엔드 컴포넌트 (backend/app/)

1.1 API 계층 (api/)

HTTP 요청과 응답 변환, 입력 검증(Pydantic), 인증 의존성 주입을 맡습니다. 비즈니스 로직은 넣지 않습니다.

컴포넌트 책임 관련 스토리
table_auth_router 태블릿 로그인 (토큰 발급) US-C01~C03
table_router 고객용 메뉴 조회, 주문 생성, 현재 세션 주문 조회, 상태 동기화 조회 US-C04~C15
admin_auth_router 관리자 로그인 US-A01~A03
admin_dashboard_router 대시보드 조회, 주문 상세 조회 US-A04~A07
admin_order_router 항목 준비 시작/전체 준비 시작/예상 시간 수정/완료, 주문 삭제 US-A08~A11, US-A13
admin_table_router 테이블 등록/비밀번호 변경, 이용 완료, 과거 내역 US-A12, US-A14, US-A15
sse_router 관리자 스트림(매장 채널), 태블릿 스트림(테이블 채널) US-C15, C16, A05, US-I01~I05

1.2 Core (core/)

컴포넌트 책임
config 환경 설정 (DB 경로, JWT 비밀키, 토큰 만료 16시간, 잠금 정책 5회/15분)
database SQLAlchemy 엔진/세션 생성, 요청 단위 세션 및 트랜잭션 경계
security bcrypt 해싱/검증, JWT 발급/검증. 토큰 종류는 admin, table
deps FastAPI 의존성: get_db, get_current_admin, get_current_table. 헤더 또는 쿼리 토큰을 해석하고 매장/테이블 범위 정보를 담은 컨텍스트로 변환
errors 도메인 예외 → HTTP 응답 변환. 예: InvalidStateTransition → 409, AccountLocked → 423

1.3 Service 계층 (services/)

비즈니스 로직과 트랜잭션 오케스트레이션을 맡습니다. 커밋에 성공한 뒤에만 이벤트를 발행합니다.

컴포넌트 책임
AuthService 관리자/태블릿 자격 증명 검증, 토큰 발급, 로그인 잠금 검사 연동
LoginAttemptService 로그인 실패 횟수 기록, 잠금 여부 판정, 성공 시 초기화
MenuService 매장의 카테고리별 메뉴 조회 (노출 순서 정렬)
OrderService 주문 생성(세션 자동 시작, 금액은 서버에서 계산, 주문 번호 채번), 현재 세션 주문 조회, 주문 삭제
OrderItemService 항목 상태 전이(준비 시작/전체 준비 시작/예상 시간 수정/완료), 주문 상태 자동 결정
TableService 테이블 등록/비밀번호 변경/목록 조회
TableSessionService 현재 세션 조회/생성, 이용 완료(세션 주문 보관 표시 + 세션 종료, 단일 트랜잭션)
DashboardService 테이블별 총액과 최신 주문 3개를 묶은 대시보드 뷰 생성
OrderHistoryService 테이블별 과거 주문 조회 (보관 표시된 Order를 세션별로 묶음, 날짜 필터)
EventBroker (interface) + InMemoryEventBroker 채널별 구독/발행. 채널: store:{id}, table:{id}
EventPublisher 도메인 이벤트를 SSE 이벤트로 바꿔 알맞은 채널(매장 채널 + 해당 테이블 채널)에 발행

1.4 Repository 계층 (repositories/)

SQLAlchemy 쿼리를 캡슐화합니다. 모든 조회는 store_id 범위 안에서만 합니다.

컴포넌트 대상 엔티티
StoreRepository Store
AdminUserRepository AdminUser
LoginAttemptRepository LoginAttempt (잠금 상태 저장)
TableRepository Table
TableSessionRepository TableSession
MenuRepository Category, Menu
OrderRepository Order, OrderItem (현재 주문 + 보관된 과거 주문 조회)

1.5 Model / Schema

  • models/: SQLAlchemy ORM 모델
    • Store, AdminUser, LoginAttempt, Table, TableSession, Category, Menu, Order, OrderItem
    • 과거 이력은 별도 테이블 없이 Order.archived_at으로 구분합니다
    • 컬럼 상세는 Functional Design에서 정합니다
  • schemas/: Pydantic 요청/응답 DTO와 SSE 이벤트 페이로드

1.6 Seed (seed/)

  • seed.py: 데모 매장, 관리자 계정, 테이블, 카테고리/메뉴 적재. 이미 있으면 건너뜀
  • static/images/: 플레이스홀더 메뉴 이미지. FastAPI StaticFiles로 /static에 노출

Component Methods

메서드 시그니처와 입출력 타입을 정리한 문서입니다. 상세 비즈니스 규칙(검증 수치, 상태 전이 표, 스키마)은 Functional Design에서 정의합니다.

표기 규칙

  • ctx: TableContext는 store_id, table_id, table_number를 담습니다.
  • ctx: AdminContext는 store_id, admin_id를 담습니다.
  • db: Session은 SQLAlchemy 세션입니다.
  • 모든 서비스 메서드는 ctx의 store_id 범위 밖 데이터를 다루지 않습니다.

1. Core

security

def hash_password(plain: str) -> str
def verify_password(plain: str, hashed: str) -> bool
def create_token(subject: TokenSubject, expires_in: timedelta) -> tuple[str, datetime]   # (token, expires_at)
def decode_token(token: str) -> TokenSubject        # 만료/위조 시 InvalidToken
# TokenSubject: kind("admin"|"table"), store_id, admin_id | table_id

deps

def get_db() -> Iterator[Session]
def get_current_admin(token: str = Header/Query) -> AdminContext     # kind == "admin"
def get_current_table(token: str = Header/Query) -> TableContext     # kind == "table"

def login_admin(db, store_code: str, username: str, password: str) -> TokenResponse

# TableTokenResponse: token, expires_at, store_id, table_id, table_number

def reset(db, key: LoginKey) -> None

MenuService

def list_menu(db, store_id: int) -> list[CategoryWithMenus]

OrderService

def create_order(db, ctx: TableContext, items: list[OrderItemInput]) -> OrderDTO

def list_current_session_orders(db, ctx: TableContext, cursor: int | None, limit: int) -> Page[OrderDTO]
def delete_order(db, ctx: AdminContext, order_id: int) -> OrderDeletedResult
# OrderDeletedResult: order_id, table_id, table_total
# 커밋 후 이벤트: order.deleted

OrderItemService

def start_item(db, ctx: AdminContext, item_id: int, estimated_minutes: int) -> OrderItemChange
def start_all(db, ctx: AdminContext, order_id: int, estimated_minutes: int) -> list[OrderItemChange]

def complete_item(db, ctx: AdminContext, item_id: int) -> OrderItemChange
def derive_order_status(item_statuses: list[ItemStatus]) -> OrderStatus      # 순수 함수
# OrderItemChange: item(OrderItemDTO), order_id, order_status, table_id
# 잘못된 전이: InvalidStateTransition
# 커밋 후 이벤트: order_item.updated

TableService

def list_tables(db, ctx: AdminContext) -> list[TableDTO]
def create_table(db, ctx: AdminContext, table_number: int, password: str) -> TableDTO
def change_password(db, ctx: AdminContext, table_id: int, new_password: str) -> None
# 중복 번호: DuplicateTableNumber

TableSessionService

def get_active(db, table_id: int) -> TableSession | None
def get_or_start(db, store_id: int, table_id: int) -> TableSession
def complete_session(db, ctx: AdminContext, table_id: int) -> SessionCompletedResult
# 단일 트랜잭션: 세션 주문에 archived_at 설정(보관 표시), 세션 종료 시각 기록
# 커밋 후 이벤트: table.session_completed

DashboardService

def get_dashboard(db, ctx: AdminContext) -> list[TableSummaryDTO]
# TableSummaryDTO: table_id, table_number, session_id, total_amount, order_count, unfinished_item_count, recent_orders(최대 3)
def get_order_detail(db, ctx: AdminContext, order_id: int) -> OrderDTO

OrderHistoryService

def list_history(db, ctx: AdminContext, table_id: int, date: date | None) -> list[HistoryOrderDTO]
# HistoryOrderDTO: order_no, ordered_at, items, total_amount, session_completed_at

TableStateService (재연결 동기화용, OrderService에 포함 가능)

def get_table_state(db, ctx: TableContext) -> TableStateDTO
# TableStateDTO: session_id | None, orders(현재 세션 전체), server_time

EventBroker / EventPublisher

class EventBroker(Protocol):
    async def subscribe(self, channel: str) -> AsyncIterator[Event]
    def publish(self, channel: str, event: Event) -> None     # 동기 코드(서비스)에서 호출 가능

class InMemoryEventBroker(EventBroker): ...                     # 채널별 asyncio.Queue 목록

class EventPublisher:
    def order_created(self, order: OrderDTO) -> None              # store:{id}, table:{id}
    def order_deleted(self, result: OrderDeletedResult) -> None   # store:{id}, table:{id}
    def order_items_updated(self, changes: list[OrderItemChange]) -> None
    def session_completed(self, result: SessionCompletedResult) -> None
# Event: type(str), data(dict), id(단조 증가)

3. Repositories (주요 메서드)

StoreRepository.get_by_code(db, code) -> Store | None
AdminUserRepository.get_by_username(db, store_id, username) -> AdminUser | None
LoginAttemptRepository.get(db, key) -> LoginAttempt | None ; upsert(db, attempt)
TableRepository.get(db, store_id, table_id) ; get_by_number(db, store_id, number) ; list(db, store_id) ; add(db, table)
TableSessionRepository.get_active(db, table_id) ; add(db, session)
MenuRepository.list_categories_with_menus(db, store_id) ; get_menus(db, store_id, menu_ids)

서비스 공통 원칙

  • 트랜잭션 경계
    • 쓰기를 하는 서비스 메서드 1회 호출이 DB 트랜잭션 1개입니다.
    • 라우터가 get_db 세션을 넘기고, 서비스가 커밋/롤백을 결정합니다.
  • 커밋 후 발행
    • SSE 이벤트는 커밋이 성공한 뒤에만 EventPublisher로 발행합니다.
    • 롤백되면 이벤트도 발행하지 않습니다. US-A13 AC3, US-A14 AC4를 이 원칙으로 충족합니다.
  • 범위 강제
    • 모든 조회와 변경은 ctx.store_id로 제한합니다.
    • 태블릿 요청은 추가로 ctx.table_id로 제한합니다 (US-I06).
  • 서버 기준 계산: 주문 금액, 주문 번호, 예상 완료 시각, 주문 상태는 서버만 계산합니다. 클라이언트가 보낸 값은 신뢰하지 않습니다.
  • 도메인 예외: 서비스는 도메인 예외만 던지고, core.errors가 HTTP 상태로 변환합니다.

주요 오케스트레이션 흐름

S1. 태블릿 로그인 / 자동 재로그인 (US-C01~C03)

  1. table_auth_router가 AuthService.login_table을 호출합니다.
  2. LoginAttemptService.ensure_not_locked로 잠금 여부를 확인합니다.
  3. StoreRepository.get_by_code, TableRepository.get_by_number로 매장과 테이블을 찾습니다.
  4. security.verify_password로 비밀번호를 확인합니다.
    • 실패: record_failure 후 InvalidCredentials
    • 성공: reset 후 16시간 table 토큰 발급
  5. 프론트엔드 apiClient는 table 요청이 401을 받으면 tableAuthStore.relogin()을 1회 시도합니다.
    • 재로그인 성공: 원래 요청을 재시도합니다.
    • 재로그인 실패: /table/setup으로 이동합니다.

S2. 주문 생성 (US-C10~C12, US-I01)

  1. table_router가 OrderService.create_order(ctx, items)를 호출합니다.
  2. MenuRepository.get_menus로 메뉴를 가져옵니다. 매장 메뉴가 아닌 항목이 있으면 거부합니다.
  3. TableSessionService.get_or_start로 활성 세션을 가져오고, 없으면 새로 만듭니다.
  4. OrderRepository.next_order_no로 주문 번호를 채번합니다.
  5. Order와 OrderItem을 생성합니다. 메뉴명/단가 스냅샷을 저장하고 모든 항목을 대기중으로 둡니다.
  6. 커밋합니다.
  7. EventPublisher.order_created가 store:{id}와 table:{id} 채널에 발행합니다.
  8. 응답으로 OrderDTO(주문 번호 포함)를 돌려줍니다.
    • 프론트엔드는 장바구니를 비우고 성공 화면을 보여준 뒤 5초 후 메뉴 화면으로 이동합니다.
    • 실패 응답이면 장바구니를 유지합니다.

S3. 메뉴 항목 상태 변경 (US-A08~A11, US-I02)

  1. admin_order_router가 OrderItemService의 메서드 중 하나를 호출합니다.
    • start_item, start_all, update_estimate, complete_item
  2. OrderRepository.get_item으로 항목을 가져오고 매장 범위를 확인합니다.
  3. 상태 전이가 유효한지 검사합니다. 유효하지 않으면 InvalidStateTransition입니다.
  4. 상태, 예상 완료 시각, 완료 시각을 갱신합니다.
  5. derive_order_status로 주문 상태를 다시 계산해 저장합니다.
  6. 커밋합니다.
  7. EventPublisher.order_items_updated가 매장 채널과 테이블 채널에 발행합니다.
    • 태블릿 TableEventBridge는 항목이 완료로 바뀌면 완료 토스트를 띄웁니다 (US-C16).

S4. 주문 삭제 (US-A13, US-I04)

  1. OrderService.delete_order가 주문을 조회하고 매장 범위를 확인합니다.
  2. 주문과 그 항목들을 삭제합니다.
  3. 세션 총액을 다시 계산합니다.
  4. 커밋합니다.
  5. order.deleted 이벤트를 발행합니다. 페이로드에는 table_total이 들어갑니다.

S5. 이용 완료 (US-A14, US-I03)

  1. TableSessionService.complete_session(ctx, table_id)를 호출합니다.
  2. 활성 세션을 조회합니다. 세션이 없으면 아무것도 처리하지 않고 성공을 돌려줍니다. 리셋할 대상이 없기 때문입니다.
  3. 아래 작업을 단일 트랜잭션으로 처리합니다.
    1. 세션의 모든 주문에 archived_at = 이용 완료 시각을 설정합니다(보관 표시). 주문 데이터는 삭제하거나 복사하지 않습니다.
    2. 세션에 종료 시각을 기록하고 비활성화합니다.
    3. 이후 현재 주문 조회와 대시보드 총액은 archived_at IS NULL인 활성 세션 주문만 대상으로 합니다.
  4. 커밋합니다. 실패하면 전체 롤백하고 이벤트도 발행하지 않습니다.
  5. table.session_completed 이벤트를 발행합니다.
    • 대시보드는 해당 카드를 0원으로 리셋합니다.
    • 태블릿은 장바구니와 주문 내역을 초기화하고 메뉴 화면으로 이동합니다.

S6. 실시간 구독과 재연결 동기화 (US-I05)

  1. sse_router가 쿼리 토큰을 deps로 검증하고 채널을 결정합니다.
    • admin 토큰: store:{store_id}
    • table 토큰: table:{table_id}
  2. EventBroker.subscribe(channel)의 결과를 text/event-stream으로 스트리밍합니다. 15초마다 ping을 보냅니다.
  3. 클라이언트가 연결을 끊으면 구독 큐를 정리합니다.
  4. 프론트엔드 useEventStream이 재연결을 맡습니다.
    • 연결 오류가 나면 지수 백오프로 재연결합니다 (최대 10초).
    • 재연결되면 onResync를 호출합니다.
  5. onResync에서 화면별로 전체 상태를 다시 조회합니다.
    • 관리자: GET /api/admin/dashboard
    • 태블릿: GET /api/table/state
    • 태블릿은 서버 응답의 session_id가 로컬에 저장한 값과 다르거나 null이면 장바구니도 비웁니다 (US-I03 AC3).

S7. 관리자 로그인 / 만료 (US-A01~A03)

  • 흐름은 S1과 같습니다. LoginKey는 ("admin", store_code, username)입니다.
  • 프론트엔드 adminAuthStore는 expiresAt이 되면 타이머로 자동 로그아웃합니다.
  • 그 전이라도 API가 401을 받으면 즉시 로그아웃합니다.

Component Dependency

1. 계층 의존 규칙

  • 의존 방향은 위에서 아래로만 흐릅니다.
    • 백엔드: api → services → repositories → models
    • core는 모든 계층이 사용할 수 있습니다.
  • 금지되는 의존
    • repositories는 services를 참조하지 않습니다.
    • services는 FastAPI(Request, HTTPException)를 참조하지 않습니다.
  • 이벤트 흐름: services가 EventPublisher를 호출하고, EventPublisher가 EventBroker에 발행합니다. 구독은 sse_router가 EventBroker에 직접 합니다.
  • 프론트엔드 의존 방향: pages/components → stores → api → shared/apiClient
    • 고객용 table/과 관리자용 admin/은 서로 참조하지 않고, shared/만 함께 씁니다.
