Components

설계 결정 요약 (application-design-plan.md 답변)

항목 결정
프론트엔드 React+Vite 앱 1개. /table/* 고객용, /admin/* 관리자용
백엔드 구조 계층형: router → service → repository
DB 접근 SQLAlchemy 2.0 (SQLite)
SSE 전달 프로세스 내부 메모리 브로커(asyncio 큐). EventBroker 인터페이스로 분리. 서버는 프로세스 1개로 실행
SSE 페이로드 변경된 데이터를 이벤트에 포함. 재연결 시에만 전체 상태를 다시 조회
SSE 인증 토큰을 쿼리 파라미터로 전달 (?token=)
프론트 상태 관리 Zustand (+ persist로 localStorage 저장)
저장소 구조 backend/, frontend/, 루트 docker-compose.yml

1. 백엔드 컴포넌트 (backend/app/)

1.1 API 계층 (api/)

HTTP 요청과 응답 변환, 입력 검증(Pydantic), 인증 의존성 주입을 맡습니다. 비즈니스 로직은 넣지 않습니다.

컴포넌트 책임 관련 스토리
table_auth_router 태블릿 로그인 (토큰 발급) US-C01~C03
table_router 고객용 메뉴 조회, 주문 생성, 현재 세션 주문 조회, 상태 동기화 조회 US-C04~C15
admin_auth_router 관리자 로그인 US-A01~A03
admin_dashboard_router 대시보드 조회, 주문 상세 조회 US-A04~A07
admin_order_router 항목 준비 시작/전체 준비 시작/예상 시간 수정/완료, 주문 삭제 US-A08~A11, US-A13
admin_table_router 테이블 등록/비밀번호 변경, 이용 완료, 과거 내역 US-A12, US-A14, US-A15
sse_router 관리자 스트림(매장 채널), 태블릿 스트림(테이블 채널) US-C15, C16, A05, US-I01~I05

1.2 Core (core/)

컴포넌트 책임
config 환경 설정 (DB 경로, JWT 비밀키, 토큰 만료 16시간, 잠금 정책 5회/15분)
database SQLAlchemy 엔진/세션 생성, 요청 단위 세션 및 트랜잭션 경계
security bcrypt 해싱/검증, JWT 발급/검증. 토큰 종류는 admin, table
deps FastAPI 의존성: get_db, get_current_admin, get_current_table. 헤더 또는 쿼리 토큰을 해석하고 매장/테이블 범위 정보를 담은 컨텍스트로 변환
errors 도메인 예외 → HTTP 응답 변환. 예: InvalidStateTransition → 409, AccountLocked → 423

1.3 Service 계층 (services/)

비즈니스 로직과 트랜잭션 오케스트레이션을 맡습니다. 커밋에 성공한 뒤에만 이벤트를 발행합니다.

컴포넌트 책임
AuthService 관리자/태블릿 자격 증명 검증, 토큰 발급, 로그인 잠금 검사 연동
LoginAttemptService 로그인 실패 횟수 기록, 잠금 여부 판정, 성공 시 초기화
MenuService 매장의 카테고리별 메뉴 조회 (노출 순서 정렬)
OrderService 주문 생성(세션 자동 시작, 금액은 서버에서 계산, 주문 번호 채번), 현재 세션 주문 조회, 주문 삭제
OrderItemService 항목 상태 전이(준비 시작/전체 준비 시작/예상 시간 수정/완료), 주문 상태 자동 결정
TableService 테이블 등록/비밀번호 변경/목록 조회
TableSessionService 현재 세션 조회/생성, 이용 완료(세션 주문 보관 표시 + 세션 종료, 단일 트랜잭션)
DashboardService 테이블별 총액과 최신 주문 3개를 묶은 대시보드 뷰 생성
OrderHistoryService 테이블별 과거 주문 조회 (보관 표시된 Order를 세션별로 묶음, 날짜 필터)
EventBroker (interface) + InMemoryEventBroker 채널별 구독/발행. 채널: store:{id}, table:{id}
EventPublisher 도메인 이벤트를 SSE 이벤트로 바꿔 알맞은 채널(매장 채널 + 해당 테이블 채널)에 발행

1.4 Repository 계층 (repositories/)

SQLAlchemy 쿼리를 캡슐화합니다. 모든 조회는 store_id 범위 안에서만 합니다.

컴포넌트 대상 엔티티
StoreRepository Store
AdminUserRepository AdminUser
LoginAttemptRepository LoginAttempt (잠금 상태 저장)
TableRepository Table
TableSessionRepository TableSession
MenuRepository Category, Menu
OrderRepository Order, OrderItem (현재 주문 + 보관된 과거 주문 조회)

1.5 Model / Schema

  • models/: SQLAlchemy ORM 모델
    • Store, AdminUser, LoginAttempt, Table, TableSession, Category, Menu, Order, OrderItem
    • 과거 이력은 별도 테이블 없이 Order.archived_at으로 구분합니다
    • 컬럼 상세는 Functional Design에서 정합니다
  • schemas/: Pydantic 요청/응답 DTO와 SSE 이벤트 페이로드

1.6 Seed (seed/)

  • seed.py: 데모 매장, 관리자 계정, 테이블, 카테고리/메뉴 적재. 이미 있으면 건너뜀
  • static/images/: 플레이스홀더 메뉴 이미지. FastAPI StaticFiles로 /static에 노출

2. 프론트엔드 컴포넌트 (frontend/src/)

2.1 공통 (shared/)

컴포넌트 책임
apiClient fetch 래퍼. 토큰 첨부, 에러 정규화. 401 처리는 앱별 핸들러에 위임
useEventStream EventSource 연결, 이벤트 타입별 핸들러 등록, 자동 재연결, 재연결 시 onResync 호출
ConfirmDialog, Toast, Button 등 UI 공통 UI. 터치 영역 최소 44x44px
format 금액/시각/남은 시간 포맷 유틸

2.2 고객용 (table/, 경로 /table/*)

컴포넌트 종류 책임 관련 스토리
tableAuthStore Zustand(persist) 매장코드/테이블번호/비밀번호/토큰 저장, 자동 재로그인 C01~C03
cartStore Zustand(persist) 장바구니 항목, 수량, 총액 계산, 비우기 C06~C09
tableOrdersStore Zustand 현재 세션 주문 목록, SSE 이벤트 반영 C13~C15, I02~I04
tableApi API 모듈 로그인, 메뉴, 주문 생성, 주문 조회, 상태 조회. 401이면 재로그인 후 재시도 C01~C15
TableSetupPage Page 초기 설정 폼 C01
MenuPage Page 카테고리 탭 + 메뉴 카드 그리드 (기본 화면) C04, C05
CategoryTabs, MenuCard Component 빠른 이동, 메뉴 정보/담기 C04~C06
CartDrawer Component 수량 조절/삭제/비우기/총액 C06~C09
OrderConfirmPage Page 최종 확인, 주문 확정, 실패 처리 C10, C12
OrderSuccessPage Page 주문 번호 표시, 5초 후 메뉴로 이동 C11
OrderHistoryPage Page 현재 세션 주문 목록, 무한 스크롤 C13
OrderItemStatusBadge Component 항목 상태, 남은 시간 카운트다운, "곧 나옵니다" C14
TableEventBridge Component 테이블 채널 SSE 구독. 완료 토스트 표시, 이용 완료 시 장바구니/주문 초기화 C15, C16, I02~I05
TableLayout Layout 상단 바(주문 내역/장바구니 버튼), 토스트 영역, 인증 가드 전체

2.3 관리자용 (admin/, 경로 /admin/*)

컴포넌트 종류 책임 관련 스토리
adminAuthStore Zustand(persist) JWT와 만료 시각 저장, 만료되면 자동 로그아웃 A01, A02
dashboardStore Zustand 테이블별 카드 데이터, 신규 주문 강조 상태, 필터, SSE 이벤트 반영 A04~A07, I01
adminApi API 모듈 관리자 API 호출. 401이면 로그아웃 A01~A15
AdminLoginPage Page 로그인 폼, 잠금 안내 A01, A03
DashboardPage Page 테이블 그리드, 필터, SSE 구독 A04~A07
TableCard Component 총액, 최신 주문 3개, 신규 강조, 이용 완료/과거 내역 버튼 A04, A05, A14
TableFilter Component 테이블 다중 선택 필터 A07
OrderDetailModal Component 전체 항목, 항목별 상태 버튼, 전체 준비 시작, 주문 삭제 A06, A08~A11, A13
EstimateInputDialog Component 소요 시간(분) 입력 및 검증 A08~A10
TableHistoryModal Component 과거 내역, 날짜 필터, 닫기 A15
TableManagementPage Page 테이블 등록/비밀번호 변경 A12
AdminLayout Layout 내비게이션, 인증 가드 전체

3. 실행/배포 구성 (루트)

  • docker-compose.yml: backend(uvicorn, 단일 워커, SQLite 볼륨)와 frontend(Vite 빌드 결과를 정적 서빙, 또는 dev 서버)
  • 프론트엔드의 /api, /static 요청은 백엔드로 프록시
    • 개발 환경: Vite proxy
    • Docker 환경: nginx 등
  • 로컬 직접 실행 스크립트/가이드 포함
