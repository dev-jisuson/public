Inception · 유닛 · docs/tableorder/inception/application-design/unit-of-work.md

Unit of Work

결정 사항 (unit-of-work-plan.md 답변)

  • 단위 수: 2개 — backend, frontend
  • 구현 순서: backend 먼저 → frontend
  • API 타입: 백엔드 Pydantic 스키마를 기준으로 프론트엔드 TypeScript 타입을 직접 작성 (frontend/src/shared/types.ts)

배포 모델

  • 독립 배포 서비스(마이크로서비스)가 아닙니다. 두 단위를 Docker Compose 하나로 함께 실행하는 하나의 애플리케이션입니다.
  • 두 단위는 REST와 SSE 계약으로만 통신합니다. 코드나 패키지를 서로 직접 참조하지 않습니다.

Unit 1: backend

항목 내용
목적 테이블오더 API 서버. 인증, 메뉴, 주문, 메뉴 항목 상태, 테이블 세션, 실시간 이벤트(SSE), seed 데이터를 맡습니다
기술 Python, FastAPI, SQLAlchemy 2.0, SQLite, PyJWT, bcrypt, pytest
실행 uvicorn 단일 워커. 메모리 이벤트 브로커를 쓰기 때문에 워커는 1개여야 합니다
포함 컴포넌트 components.md 1절 전체 (API 라우터 7개, core, 서비스 10개, 리포지토리 7개, 모델/스키마, seed, 정적 이미지)
다음 단계 Functional Design → Code Generation
완료 기준 pytest 통과, seed 적재 후 모든 엔드포인트와 SSE 이벤트가 component-methods.md 계약대로 동작

Unit 2: frontend

항목 내용
목적 고객용 태블릿 화면(/table/*)과 관리자 화면(/admin/*)을 담은 React+Vite 앱 1개
기술 TypeScript, React, Vite, React Router, Zustand(persist), Vitest
실행 개발: Vite dev 서버(/api, /static은 백엔드로 프록시) / Docker: 빌드 결과를 nginx로 서빙하고 프록시
포함 컴포넌트 components.md 2절 전체 (shared, table, admin)
다음 단계 Code Generation (Functional Design 생략 — execution-plan.md 참고)
완료 기준 npm run build 성공, Vitest 통과, 실제 backend에 연결해서 스토리 인수 조건 동작

코드 구성 전략 (Greenfield multi-unit)

워크스페이스 루트에 단위별 디렉터리를 둡니다 ({unit-name}/ 패턴).

tableorder/
+-- docker-compose.yml
+-- README.md                      # 실행 방법 (Docker / 로컬)
+-- backend/
|   +-- pyproject.toml
|   +-- Dockerfile
|   +-- app/
|   |   +-- main.py                # FastAPI 앱, 라우터 등록, StaticFiles
|   |   +-- api/                   # routers
|   |   +-- core/                  # config, database, security, deps, errors
|   |   +-- services/              # 비즈니스 로직 + EventBroker/Publisher
|   |   +-- repositories/
|   |   +-- models/                # SQLAlchemy ORM
|   |   +-- schemas/               # Pydantic DTO, SSE 페이로드
|   |   +-- seed/                  # seed.py, seed 데이터
|   +-- static/images/             # 플레이스홀더 메뉴 이미지
|   +-- tests/                     # pytest (unit + API)
+-- frontend/
    +-- package.json
    +-- vite.config.ts             # dev proxy
    +-- Dockerfile
    +-- nginx.conf
    +-- index.html
    +-- src/
        +-- main.tsx, App.tsx      # 라우팅 (/table/*, /admin/*)
        +-- shared/                # apiClient, useEventStream, types.ts, UI, format
        +-- table/                 # stores, api, pages, components
        +-- admin/                 # stores, api, pages, components
        +-- (*.test.ts[x])         # Vitest, 대상 파일 옆에 둠
  • 문서는 aidlc-docs/에만 둡니다. 애플리케이션 코드는 위 경로에만 둡니다.
  • 데이터 파일: SQLite DB는 backend/data/tableorder.db에 둡니다. Docker 실행 시에는 볼륨에 마운트합니다. 이 경로는 git에서 제외합니다.
