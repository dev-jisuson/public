요구사항 명확화 질문 (Requirements Clarification Questions)

제공해주신 요구사항 정의서와 예외사항 문서를 분석했습니다. 요구사항은 기능적으로 매우 상세하지만, 구현을 위한 기술 스택 / 아키텍처 / 데이터 저장소 등 핵심 기술 결정 사항이 명시되지 않았습니다. 아래 질문에 [Answer]: 태그 뒤에 선택지 letter(A, B, C...)를 입력해 주세요. 맞는 선택지가 없으면 마지막 "Other"를 선택하고 설명을 적어주세요.

Question 1

백엔드 서버는 어떤 기술 스택으로 구현할까요?

A) Node.js (Express/NestJS) + TypeScript

B) Python (FastAPI/Django)

C) Java/Kotlin (Spring Boot)

D) Go

X) Other (please describe after [Answer]: tag below)

Answer B (FastAPI)

Question 2

프론트엔드(고객용 웹UI + 관리자용 웹UI)는 어떤 프레임워크로 구현할까요?

A) React (+ Vite 또는 Next.js)

B) Vue.js

C) Svelte/SvelteKit

D) 서버 사이드 렌더링 템플릿 (별도 SPA 프레임워크 미사용)

X) Other (please describe after [Answer]: tag below)

Answer A(Vite / Next.js 둘 중 하나 가벼운걸로)

Question 3

데이터 저장소는 무엇을 사용할까요? (매장, 메뉴, 주문, 주문이력, 세션 저장)

A) 관계형 DB - PostgreSQL

B) 관계형 DB - MySQL

C) 관계형 DB - SQLite (경량, 로컬 개발/MVP용)

D) NoSQL Document - MongoDB

X) Other (please describe after [Answer]: tag below)

Answer C

Question 4

배포/실행 환경은 어떻게 가정할까요?

A) 로컬 개발 환경 중심 (Docker Compose로 로컬 실행, MVP 데모 목적)

B) AWS 클라우드 (ECS/Lambda 등)

C) 기타 클라우드 (Azure/GCP)

D) 아직 결정하지 않음 — 코드 레벨 구현에만 집중

X) Other (please describe after [Answer]: tag below)

Answer A (Docker 는 설치 안되었으면 그냥 로컬에서 실행해도됨. MVP 고려.)

Question 5

고객용 태블릿 자동 로그인 시 "로컬 저장" 및 장바구니 유지는 어떤 방식으로 구현할까요?

A) 브라우저 localStorage 사용

B) 브라우저 쿠키 + 서버 세션

C) IndexedDB

X) Other (please describe after [Answer]: tag below)

Answer A

Question 6

관리자 실시간 주문 모니터링은 요구사항에 SSE(Server-Sent Events)로 명시되어 있습니다. 이 방식을 그대로 사용할까요?

A) 예, SSE 사용 (요구사항 그대로)

B) 아니요, WebSocket으로 대체

C) 아니요, 폴링(polling) 방식으로 단순화

X) Other (please describe after [Answer]: tag below)

Answer A

Question 7

메뉴 이미지는 "이미지 URL" 필드로 관리된다고 되어 있고, 이미지 업로드/리사이징은 제외 대상입니다. 이미지는 어떻게 처리할까요?

A) 외부 URL 문자열만 저장 (실제 업로드 없음, 요구사항 그대로)

B) 로컬 정적 파일 경로 참조

X) Other (please describe after [Answer]: tag below)

Answer B

Question 8

MVP 범위를 요구사항 문서의 "4. MVP 개발 범위"에 명시된 핵심 기능으로 한정할까요?

A) 예, 문서의 MVP 범위대로 (고객용 5개 + 관리자용 3개 기능 그룹)

B) 아니요, 일부 기능 추가/제외 필요 (Other에 설명)

X) Other (please describe after [Answer]: tag below)

Answer B + 고객용: 메뉴가 나오기까지 예상 시간 표시, 서빙 직전에 완료됨 확 / 관리자용: 메뉴 준비 시작하면서 예상 시각 입력. 테이블 서빙 직전에 완료 처리.

Question 9

주문 상태(대기중/준비중/완료) 변경 권한과 흐름은 관리자만 수행하는 것으로 가정하면 될까요?

A) 예, 관리자만 주문 상태를 변경 (고객은 조회만)

B) 아니요, 고객도 일부 상태 변경 가능 (Other에 설명)

X) Other (please describe after [Answer]: tag below)

Answer A

Extension Opt-In 질문

AI-DLC는 선택적으로 적용할 수 있는 확장(extension) 규칙들을 제공합니다. 이 프로젝트에 어떤 확장을 적용할지 선택해 주세요.

Question: Security Extensions

이 프로젝트에 보안(SECURITY) 확장 규칙을 적용(강제)할까요?

A) Yes — 모든 SECURITY 규칙을 blocking 제약으로 강제 (프로덕션급 애플리케이션 권장)

B) No — SECURITY 규칙 생략 (PoC, 프로토타입, 실험 프로젝트에 적합)

X) Other (please describe after [Answer]: tag below)

Answer B

Question: Property-Based Testing Extension

이 프로젝트에 속성 기반 테스트(PBT) 규칙을 적용(강제)할까요?

A) Yes — 모든 PBT 규칙을 blocking 제약으로 강제 (비즈니스 로직/데이터 변환/직렬화/상태 컴포넌트가 있는 프로젝트 권장)

B) Partial — 순수 함수 및 직렬화 라운드트립에만 PBT 적용 (알고리즘 복잡도가 제한적인 프로젝트에 적합)

C) No — PBT 규칙 생략 (단순 CRUD, UI 전용, 얇은 통합 계층에 적합)

X) Other (please describe after [Answer]: tag below)

Answer C

Question: Resiliency Extensions

이 프로젝트에 복원력(Resiliency) 기준선을 적용할까요? (AWS Well-Architected Reliability Pillar 기반의 설계 시점 모범 사례 — 프로덕션 보증이 아닌 "첫 초안" 가이드)

A) Yes — 복원력 기준선을 설계 시점 가이드로 적용 (비즈니스 크리티컬 워크로드 권장)

B) No — 복원력 기준선 생략 (PoC, 프로토타입, 빠른 반복이 중요한 실험 프로젝트에 적합)

X) Other (please describe after [Answer]: tag below)

Answer B
