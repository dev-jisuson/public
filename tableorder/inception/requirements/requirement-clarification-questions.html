요구사항 확인 질문 (Requirements Clarification Questions)

답변 감사합니다. Q8에 추가하신 "예상 시간 표시 / 서빙 직전 완료 처리" 기능은 구현 방식에 따라 해석이 달라질 수 있어서 아래 내용을 확인하려고 합니다. [Answer]: 태그 뒤에 선택지 letter를 입력해 주세요.

참고로 다음 항목들은 제가 임의로 결정했습니다. 다르게 하고 싶으시면 알려주세요.

  • Q2 프론트엔드: React + Vite로 진행합니다 (Next.js보다 가볍고 SPA 용도로 충분합니다)
  • Q4 실행 환경: Docker 29.9.0이 설치되어 있어 Docker Compose로 실행하는 것을 기본으로 하고, 로컬에서 직접 실행하는 방법도 함께 제공합니다
  • Security extension은 사용하지 않기로 하셨지만, 요구사항 문서에 명시된 보안 기능(bcrypt 해싱, JWT, 로그인 시도 제한)은 기능 요구사항으로 그대로 구현합니다

Ambiguity 1: 예상 시간을 어떤 단위로 관리할지

Q8에서 "메뉴가 나오기까지 예상 시간"이라고 하셨습니다. 그런데 하나의 주문에 메뉴가 여러 개 들어갈 수 있어서, 예상 시간을 어느 단위로 입력할지 정해야 합니다.

Clarification Question 1

예상 시간은 어느 단위로 입력/표시할까요?

A) 주문 단위 — 주문 1건당 예상 시간 1개 (주문 전체가 준비되는 시간)

B) 메뉴 항목 단위 — 주문 안의 각 메뉴마다 예상 시간을 따로 입력

X) Other (please describe after [Answer]: tag below)

Answer B

Ambiguity 2: 관리자가 예상 시간을 입력하는 형식

관리자 쪽 설명에는 "예상 시각 입력"이라고 되어 있고, 고객 쪽 설명에는 "예상 시간 표시"라고 되어 있습니다.

Clarification Question 2

관리자는 예상 시간을 어떤 형식으로 입력할까요?

A) 소요 시간(분) 입력 — 예: "15분" (시스템이 완료 예정 시각을 자동으로 계산)

B) 완료 예정 시각을 직접 입력 — 예: "12:45"

C) 미리 정해둔 버튼 중에서 선택 — 예: 5/10/15/20/30분

X) Other (please describe after [Answer]: tag below)

Answer A

Clarification Question 3

고객 화면에는 예상 시간을 어떻게 보여줄까요?

A) 남은 시간 카운트다운 — 예: "약 12분 남음"

B) 완료 예정 시각 — 예: "12:45 완료 예정"

C) 둘 다 표시A

X) Other (please describe after [Answer]: tag below)

Answer

Ambiguity 3: 상태 전환 규칙

"메뉴 준비 시작하면서 예상 시각 입력"이라고 하셨습니다. 이 말이 대기중 → 준비중으로 바꿀 때 예상 시간을 꼭 입력해야 한다는 뜻인지 확인이 필요합니다.

Clarification Question 4

대기중 → 준비중으로 상태를 바꿀 때 예상 시간 입력을 필수로 할까요?

A) 필수 — 예상 시간을 입력해야만 "준비중"으로 바꿀 수 있음

B) 선택 — 입력하지 않아도 "준비중"으로 바꿀 수 있고, 나중에 입력/수정 가능

X) Other (please describe after [Answer]: tag below)

Answer A

Clarification Question 5

"준비중"인 주문의 예상 시간을 관리자가 나중에 수정할 수 있어야 할까요? (예: 주방이 바빠져서 시간이 늦어지는 경우)

A) 예, 수정할 수 있음

B) 아니요, 한 번 입력하면 고정

X) Other (please describe after [Answer]: tag below)

Answer A

Ambiguity 4: 고객 화면의 상태 업데이트 방식

원래 요구사항에서는 고객 화면의 주문 상태 실시간 업데이트가 "선택사항"이었습니다. 하지만 고객이 예상 시간과 "완료됨"을 확인하려면 화면이 새로고침 없이 갱신되어야 합니다.

Clarification Question 6

고객 화면의 주문 상태와 예상 시간은 어떻게 업데이트할까요?

A) SSE로 실시간 업데이트 (관리자 화면과 같은 방식)

B) 주기적으로 서버에 다시 요청 (예: 10초마다)

C) 고객이 주문 내역 화면을 직접 열거나 새로고침할 때만 업데이트

X) Other (please describe after [Answer]: tag below)

Answer A

Clarification Question 7

주문이 "완료"로 바뀌면 고객에게 어떻게 알려줄까요? (참고: 소리/진동/푸시 알림은 예외사항에 따라 구현하지 않습니다)

A) 주문 내역 화면에서 상태 표시만 "완료"로 바뀜

B) 상태 표시 변경 + 지금 보고 있는 화면(메뉴 화면 포함)에 눈에 띄는 배너/토스트 표시

X) Other (please describe after [Answer]: tag below)

Answer B

Ambiguity 5: 메뉴 이미지 정적 파일 (Q7: B)

Clarification Question 8

메뉴 이미지 파일은 어떻게 준비할까요? (참고: 이미지 업로드 기능은 예외사항이라 만들지 않습니다)

A) 개발자/운영자가 서버의 정적 폴더(예: static/images/)에 파일을 직접 넣고, 관리자가 메뉴를 등록할 때 파일 경로를 입력

B) A와 같은 방식 + 데모용 샘플 메뉴와 플레이스홀더 이미지를 seed 데이터로 함께 제공

X) Other (please describe after [Answer]: tag below)

Answer B
