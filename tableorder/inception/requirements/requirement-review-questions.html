요구사항 재검토 확인 질문 (Requirements Review Questions)

원본 요구사항 문서, 예외사항 문서, 지금까지의 답변, 그리고 requirements.md를 다시 대조했습니다. 그 결과 원본 문서끼리 서로 맞지 않는 부분과 아직 정해지지 않은 부분을 찾았습니다. [Answer]: 태그 바로 뒤에 선택지 letter를 입력해 주세요.

Issue 1: 메뉴 관리가 MVP 범위에 들어가는지 (원본 문서 내 불일치)

원본 3.2.4절에는 메뉴 관리(등록/수정/삭제/순서 조정)가 기능 요구사항으로 정의되어 있습니다. 그런데 4절 "MVP 개발 범위"의 관리자용 목록에는 빠져 있습니다(매장 인증, 실시간 모니터링, 테이블 관리만 있음). 현재 requirements.md에는 메뉴 관리를 포함해 두었습니다.

Question 1

메뉴 관리 기능을 이번 구현 범위에 넣을까요?

A) 포함 — 3.2.4절 전체 구현 (등록/수정/삭제/노출 순서 조정)

B) 제외 — 메뉴는 seed 데이터로만 제공하고, 관리 화면은 만들지 않음

X) Other (please describe after [Answer]: tag below)

Answer B (채팅으로 변경: "마음이 바꼇어. 메뉴관리 넣지말고, 디폴트로 주어진 메뉴기반으로 하자. 이건 mvp 니까." — 이전 답변 A 취소)

Question 2

(Q1이 A인 경우) 메뉴의 "카테고리"는 어떻게 관리할까요? 원본 문서에는 카테고리를 생성/수정하는 기능에 대한 정의가 없습니다.

A) 카테고리도 관리자가 추가/수정/삭제/순서 조정 가능

B) 카테고리는 seed 데이터로 고정, 메뉴 등록 시 기존 카테고리 중에서 선택만 가능

X) Other (please describe after [Answer]: tag below)

Answer N/A (Q1이 B로 바뀌어서 해당 없음 — 카테고리와 메뉴 모두 seed 데이터로 고정)

Issue 2: 태블릿 "16시간 세션"과 "테이블 세션"은 서로 다른 개념

원본 3.2.3-1절에는 태블릿 초기 설정 시 "16시간 세션 생성"이라고 되어 있습니다. 반면 부록의 "테이블 세션"은 "첫 주문부터 이용 완료까지"를 뜻합니다. 저는 두 가지를 별개로 해석했습니다.

  • 태블릿 인증 세션: 16시간짜리 로그인 토큰
  • 테이블 이용 세션: 식사 1회 단위

Question 3 (재작성 — 사용자 요청: "로그인 기능이 필요한건지 다시 확인")

태블릿 로그인을 어떻게 할까요?

원본 문서 확인 결과:

  • 3.1.1절과 4절 MVP 범위 모두 "테이블 태블릿 자동 로그인 및 세션 관리"를 필수로 적고 있습니다.
  • constraints.md에서 제외한 것은 "복잡한 인증(OAuth, SNS, 2FA)"뿐이고, 비밀번호 로그인 자체는 제외 대상이 아닙니다.
  • 이 로그인의 실제 역할은 "이 태블릿이 어느 매장의 몇 번 테이블인지"를 서버가 믿을 수 있게 하는 것입니다. 로그인이 없으면 URL이나 API를 아는 사람이 아무 테이블 이름으로 주문을 넣을 수 있습니다.

A) 원본대로 비밀번호 로그인 유지 + 저장된 정보로 자동 재로그인 (토큰 만료를 고객이 느끼지 못함. 비밀번호가 localStorage에 평문으로 저장됨)

B) 원본대로 비밀번호 로그인 유지, 토큰만 저장 (16시간 지나면 관리자가 다시 설정해야 함)

C) 태블릿 비밀번호 로그인 제거 — 초기 설정 때 매장ID와 테이블 번호만 입력해서 localStorage에 저장 (가장 단순함. 대신 원본 MVP 요구사항과 다르고, 다른 테이블 이름으로 주문을 넣는 것을 막지 못함. 로컬 데모용으로만 적합)

X) Other (please describe after [Answer]: tag below)

Answer A (채팅: "니 추천대로")

Question 4

관리자가 "이용 완료"를 누르지 않은 채 테이블 세션이 오래 열려 있으면 어떻게 할까요? (예: 마감 후 처리를 잊은 경우)

A) 자동 종료 없음 — 관리자가 "이용 완료"를 눌러야만 종료

B) 마지막 주문 후 일정 시간(예: 16시간)이 지나면 자동으로 이용 완료 처리

X) Other (please describe after [Answer]: tag below)

Answer A (채팅: "니 추천대로")

Issue 3: 이용 완료 시 태블릿 화면 처리

이용 완료가 되면 서버의 주문 목록은 리셋됩니다. 하지만 태블릿의 localStorage 장바구니에는 이전 고객이 담아둔 메뉴가 남아 있을 수 있습니다.

Question 5

관리자가 "이용 완료"를 누르면 해당 테이블의 태블릿은 어떻게 할까요?

A) SSE로 이벤트를 받아서 장바구니를 비우고 주문 내역을 초기화한 뒤 메뉴 화면으로 이동

B) 주문 내역만 초기화하고 장바구니는 그대로 유지

X) Other (please describe after [Answer]: tag below)

Answer A (채팅: "니 추천대로")

Issue 4: 주문 삭제와 메뉴 항목 단위 상태의 관계

메뉴 항목 단위로 상태를 관리하기로 했기 때문에(CQ1: B), 일부 메뉴는 이미 "완료"(서빙됨)인 주문이 생길 수 있습니다. 원본의 "주문 삭제"는 주문 전체를 삭제하는 기능입니다.

Question 6

주문 삭제는 어떤 단위로 할까요?

A) 주문 단위로만 삭제 (상태와 관계없이 주문 전체 삭제)

B) 주문 단위 삭제 + 주문 안의 개별 메뉴 항목 삭제도 가능 (예: 고객이 메뉴 하나만 취소)

X) Other (please describe after [Answer]: tag below)

Answer A (채팅: "니 추천대로")

이전 질문 파일의 CQ3 답변이 [Answer]: 뒤가 아니라 선택지 C 줄 끝("C) 둘 다 표시A")에 적혀 있었습니다. 현재는 A로 해석해 두었습니다.
