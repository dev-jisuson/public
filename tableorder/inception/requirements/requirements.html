테이블오더 서비스 요구사항 (Requirements)

0. Intent Analysis

  • User Request: requirements/table-order-requirements.md, requirements/constraints.md 기반으로 테이블오더 서비스 구축
  • Request Type: New Project (Greenfield)
  • Scope: System-wide (고객용 웹UI + 관리자용 웹UI + API 서버 + DB)
  • Complexity: Moderate (실시간 통신, 세션 라이프사이클, 메뉴 항목 단위 상태/예상시간 관리)
  • Requirements Depth: Standard
  • Source of Truth: 원본 요구사항 문서와 질문 파일 3개의 답변
    • requirement-verification-questions.md
    • requirement-clarification-questions.md
    • requirement-review-questions.md

1. 기술 결정 사항 (Technical Decisions)

항목 결정 근거
백엔드 Python + FastAPI Q1: B
프론트엔드 React + Vite (고객용/관리자용) Q2: A, 사용자가 "가벼운 것"을 원해서 Vite 선택
데이터베이스 SQLite Q3: C
실행 환경 로컬 — Docker Compose 기본, Docker 없이 직접 실행하는 방법도 제공 Q4: A (Docker 29.9.0 설치 확인)
클라이언트 저장 브라우저 localStorage (태블릿 로그인 정보, 장바구니) Q5: A
실시간 통신 SSE — 관리자 화면 + 고객 화면 모두 Q6: A, CQ6: A
메뉴/카테고리/이미지 seed 데이터로 고정 제공. 이미지는 서버 정적 폴더(static/images/)의 플레이스홀더 파일 Q7: B, CQ8: B, RQ1: B
인증 관리자: JWT(16시간) + bcrypt / 태블릿: 매장ID+테이블번호+비밀번호로 16시간 토큰 발급 원본 3.1.1, 3.2.1, 3.2.3, RQ3: A

Extension Configuration

  • Security Baseline: 비활성 / Property-Based Testing: 비활성 / Resiliency Baseline: 비활성
  • 참고: Security extension은 비활성이지만, 원본 요구사항의 보안 기능(bcrypt, JWT, 로그인 시도 제한)은 기능 요구사항으로 구현합니다.

용어 구분

  • 태블릿 인증 세션: 태블릿 로그인 토큰. 16시간 유효
  • 테이블 세션: 식사 1회 단위. 첫 주문 시 시작하고, 관리자가 "이용 완료"를 누르면 종료
  • 두 개념은 서로 독립적입니다.

2. 기능 요구사항 — 고객용 (Customer)

FR-C1. 테이블 태블릿 자동 로그인

  • 관리자가 태블릿에서 1회 초기 설정: 매장 식별자, 테이블 번호, 테이블 비밀번호 입력
  • 인증에 성공하면 16시간 토큰을 발급하고, 로그인 정보(매장ID/테이블번호/비밀번호)와 토큰을 localStorage에 저장
  • 다음 접속 시 또는 토큰이 만료되면 저장된 정보로 자동 재로그인. 고객은 만료를 느끼지 못함 (RQ3: A)
  • 자동 재로그인이 실패하면(예: 관리자가 비밀번호를 변경) 초기 설정 화면으로 이동
  • 알려진 위험(MVP에서 수용): 테이블 비밀번호가 태블릿 localStorage에 평문으로 저장됨

FR-C2. 메뉴 조회 및 탐색

  • 메뉴 화면이 기본 화면
  • 카테고리별 분류와 카테고리 간 빠른 이동 (탭/앵커)
  • 카드 레이아웃: 메뉴명, 가격, 설명, 이미지
  • 터치 영역 최소 44x44px
  • seed 데이터에 정의된 노출 순서대로 표시

FR-C3. 장바구니

  • 메뉴 추가/삭제, 수량 증가/감소, 장바구니 비우기
  • 총 금액 실시간 계산
  • localStorage에 저장해서 새로고침해도 유지
  • 서버에는 주문 확정 시에만 전송

FR-C4. 주문 생성

  • 주문 내역 최종 확인 후 주문 확정
  • 성공 시:
    1. 주문 번호 표시
    2. 장바구니 비우기
    3. 5초 후 메뉴 화면으로 자동 이동
  • 실패 시: 에러 메시지 표시, 장바구니 유지
  • 주문 데이터: 매장 ID, 테이블 ID, 메뉴 목록(메뉴명, 수량, 단가), 총 금액, 테이블 세션 ID
  • 테이블에 진행 중인 세션이 없으면 이 주문으로 새 세션 시작
  • 주문 항목에는 메뉴명과 단가를 주문 시점의 값으로 저장

FR-C5. 주문 내역 조회

  • 현재 테이블 세션의 주문만 표시. 이용 완료 처리된 이전 세션의 주문은 제외
  • 최신 주문을 위에 표시. 페이지네이션 또는 무한 스크롤
  • 주문별 표시: 주문 번호, 주문 시각, 메뉴/수량, 금액, 주문 상태
  • [추가] 메뉴 항목별 상태(대기중/준비중/완료)와 예상 시간 표시
    • 준비중 항목: 남은 시간 카운트다운만 표시 (예: "약 12분 남음") (RQ7: A)
    • 예상 시각이 지났는데 아직 완료되지 않은 경우: "곧 나옵니다" 안내 문구 표시
  • 상태와 예상 시간은 SSE로 실시간 반영 (CQ6: A)

FR-C6. [추가] 완료 알림

  • 메뉴 항목이 "완료"로 바뀌면 주문 내역의 상태가 바뀜
  • 동시에 지금 보고 있는 화면(메뉴 화면 포함)에 눈에 띄는 배너/토스트 표시 (CQ7: B)
  • 소리/진동/푸시 알림은 하지 않음 (constraints.md)

FR-C7. 이용 완료 시 태블릿 초기화

  • 관리자가 "이용 완료"를 누르면 해당 테이블의 태블릿이 SSE 이벤트를 받음
  • 이벤트를 받으면 장바구니와 주문 내역을 비우고 메뉴 화면으로 이동 (RQ5: A)
  • 태블릿 로그인 정보는 그대로 유지

3. 기능 요구사항 — 관리자용 (Admin)

FR-A1. 매장 인증

  • 매장 식별자 + 사용자명 + 비밀번호로 로그인
  • JWT 발급, 16시간 유효. 새로고침해도 유지되고, 만료되면 자동 로그아웃
  • 비밀번호는 bcrypt 해싱
  • 로그인 시도 제한: 연속 5회 실패하면 15분 잠금 (가정). 관리자 로그인과 태블릿 로그인 모두에 적용

FR-A2. 실시간 주문 모니터링

  • SSE로 실시간 업데이트. 신규 주문은 2초 이내 표시
  • 그리드 대시보드
    • 테이블별 카드
    • 테이블 총 주문액
    • 최신 주문 3개 미리보기 (가정)
  • 주문 카드 요약: 테이블 번호, 주문 번호, 주문 시각, 메뉴/수량(축약), 총 금액
  • 주문 카드를 클릭하면 전체 메뉴 상세 보기. 이 화면에서 메뉴 항목별 상태를 변경
  • 신규 주문은 색상/애니메이션으로 강조
  • 테이블별 필터링

FR-A3. [추가] 메뉴 항목 단위 상태 및 예상 시간 관리

  • 상태와 예상 시간은 주문 안의 메뉴 항목 단위로 관리 (CQ1: B)
  • 대기중 → 준비중
    • 예상 소요 시간(분) 입력이 필수 (CQ2: A, CQ4: A)
    • 시스템이 예상 완료 시각 = 준비 시작 시각 + 소요 시간으로 계산
  • 준비중 항목의 예상 시간은 수정 가능 (CQ5: A)
    • 수정하면 현재 시각 + 새 소요 시간으로 다시 계산 (가정)
  • 준비중 → 완료: 관리자가 테이블에 서빙하기 직전에 완료 처리
  • 상태 변경 권한은 관리자만 있음. 고객은 조회만 가능 (Q9: A)
  • 상태 전이: 대기중 → 준비중 → 완료. 되돌리기 없음 (가정)
  • 주문 전체 상태는 항목 상태로 자동 결정 (가정)
    • 모든 항목이 대기중이면 대기중
    • 모든 항목이 완료면 완료
    • 그 외에는 준비중
  • 편의 기능: 주문 단위 "전체 준비 시작". 대기중인 모든 항목에 같은 소요 시간 적용 (가정)

FR-A4. 테이블 관리

  • 초기 설정: 테이블 번호/비밀번호 등록, 태블릿 로그인 활성화
  • 주문 삭제: 주문 단위로만 삭제. 항목 상태와 관계없음 (RQ6: A)
    1. 확인 팝업
    2. 즉시 삭제
    3. 테이블 총 주문액 다시 계산
    4. 성공/실패 피드백
    5. 해당 태블릿에 SSE로 반영
  • 이용 완료 (세션 종료): 관리자가 직접 눌러야만 종료. 자동 종료 없음 (RQ4: A)
    1. 확인 팝업
    2. 현재 세션 주문에 보관 표시(archived_at = 이용 완료 시각)를 하고, 세션 종료 시각 기록. 주문 데이터는 삭제하거나 복사하지 않고 그대로 둠 (사용자 결정 2026-10-14)
    3. 테이블 현재 주문/총액을 0으로 리셋
    4. 태블릿 초기화 이벤트 전송 (FR-C7)
    5. 성공/실패 피드백
  • 과거 주문 내역
    • 테이블별, 시간 역순, 날짜 필터
    • 표시 항목: 주문 번호, 시각, 메뉴, 총액, 이용 완료 시각
    • "닫기"를 누르면 대시보드로 돌아감

FR-A5. 메뉴 관리 — 범위 제외 (RQ1: B)

  • 원본 3.2.4절의 메뉴 관리 기능은 MVP에서 구현하지 않음
  • 메뉴와 카테고리는 seed 데이터로만 제공. 수정하려면 seed 파일을 바꾸고 다시 적재

4. 데이터 및 시드

  • 주요 엔티티: Store, AdminUser, LoginAttempt, Table, TableSession, Category, Menu, Order(보관 표시 archived_at 포함), OrderItem(상태/예상시간 포함)
  • 과거 주문 내역: 원본 문서의 "OrderHistory 테이블"은 별도 테이블로 만들지 않습니다. 대신 보관 표시된 Order를 세션 ID로 묶어 조회하는 방식으로 구현합니다. 원본이 요구한 "세션 ID로 그룹화"와 "완료 시각 기록"은 그대로 충족합니다.
  • 주문 번호: 매장별로 하루 단위 순차 증가 (예: 0001, 0002…) (가정)
  • 매장/관리자 계정 생성 UI는 범위 밖이므로 seed 데이터로 제공 (가정)
  • seed 구성 (CQ8: B, RQ1: B):
    • 데모 매장 1개, 관리자 계정 1개, 테이블 여러 개
    • 카테고리/샘플 메뉴, 플레이스홀더 이미지
  • 데이터 모델은 여러 매장을 지원하는 구조 (매장 식별자 기준으로 데이터 분리)

5. 비기능 요구사항 (NFR)

  • 성능: 신규 주문, 상태 변경, 이용 완료 이벤트가 SSE로 2초 이내 반영
  • 사용성: 태블릿 터치 친화 UI (44x44px 이상), 명확한 시각적 계층
  • 신뢰성
    • 장바구니는 새로고침해도 유지
    • SSE 연결이 끊기면 자동 재연결하고, 재연결 시 최신 상태를 다시 조회
  • 보안 (기능 요구 수준)
    • bcrypt, JWT 16시간, 로그인 시도 제한
    • 매장 간 데이터 접근 차단
    • 태블릿 비밀번호 localStorage 평문 저장은 MVP에서 수용한 위험
  • 운영: Docker Compose 한 번에 실행 + 로컬 직접 실행 가이드. MVP 범위이므로 SQLite 단일 파일 DB
  • 테스트: 기본 수준
    • 백엔드: pytest (핵심 비즈니스 로직/API)
    • 프론트엔드: Vitest (핵심 로직)

6. 범위 제외

  • constraints.md 기준
    • 결제: 결제/PG/영수증/환불/포인트
    • 인증: OAuth/SNS 로그인/2FA
    • 콘텐츠: 이미지 업로드·리사이징/CMS/광고
    • 알림: 푸시·SMS·이메일·소리/진동 알림
    • 주방: 주방 전달/식재료 재고
    • 고급 기능: 분석 대시보드/매출 리포트/재고/직원 권한/예약/리뷰/다국어
    • 외부 연동: 배달·POS·SNS·지도·번역 API 연동
  • 추가 제외 (RQ1: B)
    • 메뉴 관리 (등록/수정/삭제/노출 순서 조정)
    • 카테고리 관리
  • 추가 제외 (RQ6: A): 주문 안의 개별 메뉴 항목 삭제
  • 추가 제외 (RQ4: A): 테이블 세션 자동 종료

7. 가정 사항 요약

  1. 메뉴 항목 상태로 주문 전체 상태를 자동 결정하는 규칙 (FR-A3)
  2. 예상 시간을 수정하면 현재 시각 기준으로 다시 계산
  3. 상태 되돌리기 없음
  4. 주문 단위 "전체 준비 시작" 편의 기능
  5. 로그인 연속 5회 실패하면 15분 잠금 (관리자/태블릿 공통)
  6. 대시보드 미리보기는 최신 주문 3개
  7. 매장/관리자 계정은 seed로 제공
  8. 예상 시각이 지나도 미완료면 "곧 나옵니다" 표시
  9. 주문 번호는 매장별 하루 단위 순차 증가
  10. 고객 주문 내역은 최신 주문이 위
