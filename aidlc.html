AI-DLC 소개

Claude Code 위에서 AWS AI-DLC v1.0.1을 그대로 올려 돌려보는 실습 저장소. 세미나 공개용 레퍼런스.

범위: v1.0.1 (마크다운 규칙 파일 모음). v2는 main 브랜치에 엔진이 포함되어 있지만 이번 실습 대상은 아님.

실습 사례: AI-DLC로 만든 테이블오더 MVP의 산출물 전체 → docs/tableorder 세미나 진행 순서: docs/seminar.md

왜 v1.0.1인가

  • 설치 바이너리·네트워크 호출 없음 — 외부망 차단 환경에서 바로 사용 가능
  • 규칙이 마크다운 32개로만 구성되어 있어 Claude Code가 그대로 읽을 수 있음
  • 플로우 통제는 사람(또는 CLAUDE.md 지침)이 맡음 — v2 엔진이 하는 역할을 Claude Code의 skill/command/CLAUDE.md로 대체

준비물

  • Claude Code
  • 모델 접근 경로 (Claude Code가 Anthropic API에 접속할 수 있어야 함)
  • Git

설치

git clone --branch v1.0.1 https://github.com/awslabs/aidlc-workflows.git

클론 후 디렉터리 구조:

aidlc-workflows/
└── aidlc-rules/
    ├── aws-aidlc-rules/
    │   └── core-workflow.md # 워크플로 본체 (단계 순서, 승인 게이트, audit/state 기록 규칙)
    └── aws-aidlc-rule-details/
        ├── common/          # ascii-diagram-standards, terminology, process-overview ...
        ├── inception/       # requirements-analysis, user-stories, units-generation, application-design ...
        ├── construction/    # functional-design, code-generation, build-and-test ...
        ├── operations/
        └── extensions/
            ├── security/baseline/
            ├── resiliency/baseline/
            └── testing/property-based/

Claude Code에서 쓰는 법

v1에는 aidlc config 같은 CLI가 없다. 그냥 md 파일 모음이라, Claude Code가 읽어들이게만 해 주면 된다. 아래는 v1.0.1 공식 README의 Claude Code 설치 방법이다. 두 가지를 꼭 지킨다.

  • core-workflow.md가 CLAUDE.md가 된다. 상세 규칙 폴더만 참조하면 core-workflow.md에 정의된 단계 실행 조건·승인 절차·audit.md 기록 규칙이 로드되지 않는다.
  • 상세 규칙은 .aidlc-rule-details/에 둔다. core-workflow.md는 정해진 경로(.aidlc-rule-details/, .kiro/aws-aidlc-rule-details/ 등)에서만 상세 규칙을 찾는다.

방법 1 — 프로젝트 루트 (공식 권장)

내 프로젝트 루트에서 실행한다.

cp /path/to/aidlc-workflows/aidlc-rules/aws-aidlc-rules/core-workflow.md ./CLAUDE.md
mkdir -p .aidlc-rule-details
cp -R /path/to/aidlc-workflows/aidlc-rules/aws-aidlc-rule-details/* .aidlc-rule-details/

<내-프로젝트>/
├── CLAUDE.md                # = core-workflow.md
└── .aidlc-rule-details/
    ├── common/
    ├── inception/
    ├── construction/
    ├── extensions/
    └── operations/

방법 2 — .claude/ 디렉터리

core-workflow.md를 루트가 아닌 .claude/CLAUDE.md로 복사한다. 상세 규칙 위치는 방법 1과 같다.

mkdir -p .claude
cp /path/to/aidlc-workflows/aidlc-rules/aws-aidlc-rules/core-workflow.md .claude/CLAUDE.md
mkdir -p .aidlc-rule-details
cp -R /path/to/aidlc-workflows/aidlc-rules/aws-aidlc-rule-details/* .aidlc-rule-details/

이미 CLAUDE.md가 있는 프로젝트라면 덮어쓰지 말고 core-workflow.md를 별도 파일로 둔 뒤 기존 CLAUDE.md에서 @파일경로로 임포트한다. Claude Code의 @ 임포트는 파일 단위로 문서화되어 있다(디렉터리 임포트는 문서에 없음).

설정 확인

프로젝트에서 Claude Code를 실행하고 "지금 이 프로젝트에 적용된 지침이 뭐야?"라고 물어 AI-DLC 워크플로가 잡혔는지 확인한다. 개발 요청을 하면 AI-DLC 환영 메시지와 함께 Workspace Detection부터 시작한다.

팁 — 슬래시 커맨드로 만들기

자주 쓰는 흐름이면 ~/.claude/commands/aidlc-inception.md 같은 파일로 저장해 /aidlc-inception으로 호출할 수 있다.

3단계 라이프사이클

AI-DLC v1은 Inception → Construction → Operations 세 단계로 돌아간다. 각 단계는 "항상 실행되는 스테이지"와 "조건부 스테이지"가 섞여 있고, AI가 요청·워크스페이스·복잡도를 보고 어느 조건부 스테이지를 실행할지 판단한다. 단계마다 사람이 리뷰·승인한 뒤 다음 단계로 넘어간다.

🔵 Inception — "무엇을 만들지 정하기"

AI가 체계적으로 질문하며 요구사항을 수집한다. 사용자가 답하면 AI가 작업을 개발 유닛(unit of work)으로 쪼개고 실행 계획을 수립한다.

세부 스테이지:

  • Workspace Detection (항상) — 그린필드/브라운필드 판별
  • Reverse Engineering (브라운필드일 때) — 기존 코드에서 요구사항·아키텍처 역추출
  • Requirements Analysis (항상) — 요구사항 분석 (깊이는 과제에 맞춰 자동 조절)
  • User Stories (조건부) — 유저 스토리 작성
  • Workflow Planning (항상) — 이후 어떤 스테이지를 실행·생략할지 실행 계획 확정
  • Application Design (조건부) — 애플리케이션 수준 설계
  • Units Generation (조건부) — 구현 단위로 분해

산출물 예: aidlc-docs/inception/plans/unit-of-work-plan.md, application-design/*

🟢 Construction — "실제로 만들기"

AI가 설계하고 코드를 생성한다. 비즈니스 로직 설계 → 기술 스택 선택 → 코드 및 테스트 생성까지 unit별로 진행한다.

세부 스테이지:

  • Functional Design (조건부) — 기능 설계
  • NFR Requirements / NFR Design (조건부) — 비기능 요구사항과 설계 (성능·보안·확장성 등)
  • Infrastructure Design (조건부) — 인프라 설계
  • Code Generation (항상, unit별) — 실제 코드 생성
  • Build and Test (항상) — 빌드 수행과 테스트

산출물 예: aidlc-docs/construction/<unit>/functional-design/*, 생성된 소스 코드, 테스트 결과

🟡 Operations — "배포하고 실행하기"

AI가 배포를 준비하고 모니터링 설정을 한다. 사용자가 최종 확인하고 배포한다.

⚠️ v1에서는 아직 placeholder 단계로, 상세 워크플로가 비어 있다. 운영 관련 확장은 extensions/(security, resiliency, testing 등)에서 보강한다.

산출물이 쌓이는 곳

규칙에 따라 AI가 아래 경로에 결과물을 쌓는다. 프로젝트 루트에 aidlc-docs/가 자동으로 생긴다.

aidlc-docs/
├── inception/
│   ├── plans/
│   ├── reverse-engineering/   # 브라운필드일 때만
│   ├── requirements/
│   ├── user-stories/
│   └── application-design/
├── construction/
│   ├── plans/
│   ├── <unit>/                # functional-design/, nfr-*/, infrastructure-design/, code/
│   └── build-and-test/
├── operations/
├── aidlc-state.md             # 단계별 진행 상태
└── audit.md                   # 사용자 입력·승인·AI 응답 기록

애플리케이션 코드는 aidlc-docs/ 밖(워크스페이스 루트)에 생성된다. 실제 예시는 docs/tableorder 참고 (이 저장소에서는 aidlc-docs/ → docs/tableorder/로 옮겨 둠).
